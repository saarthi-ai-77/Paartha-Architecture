# LRS-001: Learning Runtime Specification (Instruction Learning Program — ILP-001)

**Role note:** Produced under the Chief Systems Engineer role for **ILP-001 ("Instruction Learning Program")**. ACA v1.0 has reached architectural maturity (`docs/04_architecture/ACA_v1.0_Architecture.md`, `docs/13_state_model/SOS-001.md`, `docs/15_process/CPA-001.md`, `docs/04_architecture/OPERATING_ENVELOPE.md`). The objective is no longer designing neural modules or tuning code, but reasoning from first principles about how an artificial cognitive architecture acquires executable knowledge through mentor-guided explanation rather than statistical next-token pretraining.

---

## 1. Computational Definition of a Lesson

A **Lesson** $\mathcal{L}$ is a structured, goal-directed instructional unit designed to transition the cognitive system from an initial epistemic state $\mathcal{S}_t$ to a target state $\mathcal{S}_{t+1}$ with verified computational competence.

Formally, a lesson is a 5-tuple:
$$\mathcal{L} = \langle \mathcal{C}_{domain}, \mathcal{P}_{prereq}, \mathcal{E}_{explain}, \mathcal{T}_{verif}, \mathcal{R}_{refine} \rangle$$

Where:
- $\mathcal{C}_{domain}$: The active domain context ($S_{episodic}$ reserved partition).
- $\mathcal{P}_{prereq}$: Required prerequisite concepts that must be verified in $S_{semantic}$ or $S_{invariants}$ prior to lesson ingress.
- $\mathcal{E}_{explain}$: The instructional explanation payload (see §2).
- $\mathcal{T}_{verif}$: Set of verification tasks designed to test non-verbatim understanding (see §7).
- $\mathcal{R}_{refine}$: Refinement and clarification criteria triggered upon partial understanding (see §10).

A lesson is NOT an uncurated text corpus or next-token stream. It is a deterministic, interactive learning sequence.

- **Epistemic Status**: **Reasoned Hypothesis** (Derived from ILP-001 first-principles analysis).

## 2. Computational Definition of Explanation

Computationally, an **Explanation** $\mathcal{E}$ is a structured mapping that binds natural language instructions into executable computational representations across seven fundamental primitives:

$$\mathcal{E} = \langle \mathcal{E}_{entity}, \mathcal{E}_{prop}, \mathcal{E}_{rel}, \mathcal{E}_{const}, \mathcal{E}_{causal}, \mathcal{E}_{transform}, \mathcal{E}_{examples} \rangle$$

1. **Entities ($\mathcal{E}_{entity}$)**: Atomic domain symbols and objects (e.g. `Node`, `Fact`, `Variable`). Mapped to primary entries in $S_{episodic}$.
2. **Properties ($\mathcal{E}_{prop}$)**: Attributes, state variables, and value ranges associated with entities.
3. **Relationships ($\mathcal{E}_{rel}$)**: Structural, spatial, or semantic predicates binding entities (e.g. `is_a`, `depends_on`, `located_in`).
4. **Constraints ($\mathcal{E}_{const}$)**: Logical invariants and boundary conditions that must hold true across all valid states ($\forall s \in \mathcal{S}, \quad c(s) = \text{True}$). Mapped directly to $S_{invariants}$.
5. **Causal Mechanisms ($\mathcal{E}_{causal}$)**: Deterministic state transition rules ($S \xrightarrow{\text{action}} S'$). Mapped to update pathways.
6. **Abstractions / Transform Families ($\mathcal{E}_{transform}$)**: Symmetry groups, operators, and grammatical sequence patterns. Mapped to structure-matched COMPOSE operators (RC-01).
7. **Examples & Counterexamples ($\mathcal{E}_{examples}$)**: Positive instances for verification and negative boundary cases for falsification.

- **Epistemic Status**: **Reasoned Hypothesis** (Synthesized from ARS-001 and COMPOSE primitive analysis).

## 3. Computational Definition of Understanding

### 3.1 Operational Definition
A cognitive architecture **understands** an explanation $\mathcal{E}$ if and only if it constructs an internal executable representation $\mathcal{K}_{\mathcal{E}}$ across its state substrates ($S_{episodic}, S_{semantic}, S_{invariants}$) that satisfies four measurable operational criteria:

$$\text{Understand}(\mathcal{E}) \iff \text{Transfer}(\mathcal{K}_{\mathcal{E}}, \mathcal{T}_{unseen}) \land \text{Falsify}(\mathcal{K}_{\mathcal{E}}, \mathcal{C}_{inv}) \land \text{Counterfactual}(\mathcal{K}_{\mathcal{E}}) \land \text{Compress}(\mathcal{K}_{\mathcal{E}})$$

1. **Generative Transfer**: Solves unseen verification tasks $\mathcal{T}_{unseen}$ without relying on surface text matching.
2. **Contradiction Falsification**: Detects and rejects invalid claims $\mathcal{C}_{inv}$ that violate derived constraints in $S_{invariants}$.
3. **Counterfactual Invariance**: Correctly predicts state transitions under counterfactual property perturbations.
4. **Structural Compression**: Represents $\mathcal{K}_{\mathcal{E}}$ using fewer parameters than raw verbatim memory ($H(\mathcal{K}_{\mathcal{E}}) \ll H(\text{text})$).

### 3.2 Distinguishing Understanding from Text Storage
- **Text Storage (Verbatim Recall)**: Storing exact raw tokens in $S_{episodic}$ key-value entries. $H(\text{text}) \approx L \log |V|$. High retrieval fidelity for exact quotes, **0% generalization** to unseen structural shifts.
- **Understanding (Computational Knowledge)**: Extracting invariants into $S_{invariants}$ and parameterizing weights in $S_{semantic}$. Low entropy ($H < 0.5$ nats), **100% transfer** across structure-matched tasks.

- **Epistemic Status**: **Reasoned Hypothesis** (Derived from EXP-009 local entropy & EXP-020 SCAN transfer).

## 4. Internal Lesson Representation

Natural language instructions provided by a mentor are parsed into internal computational representations using existing ACA primitives:

```
[Mentor Language Instruction]
              |
              v
  [Structure-Matched COMPOSE (RC-01)] ---> Parsed Symbolic Predicate Graph
              |
              +---> Entities & Relations ----> S_episodic (Primary Entries)
              |
              +---> Invariants & Bounds -----> S_invariants (Constraint Store)
              |
              +---> Transform Families ------> COMPOSE Slot Operators
              |
              +---> Weight Adjustments ------> S_semantic (CausalTransformerLM)
```

No new neural substrates are required. Language is transformed into computation by distributing extracted primitives into $S_{episodic}$, $S_{semantic}$, and $S_{invariants}$ per SOS-001 specification.

- **Epistemic Status**: **Validated** (Reduced into SOS-001 and EXP-020 primitives).

## 5. Knowledge Construction Pipeline

The knowledge construction pipeline governs the transformation of an incoming explanation into verified substrate entries:

$$\text{Explanation } \mathcal{E} \xrightarrow{\text{Phase 1: Parse}} \text{Predicate Graph } \mathcal{G} \xrightarrow{\text{Phase 2: Consistency}} S_{invariants} \text{ Audit} \xrightarrow{\text{Phase 3: Store}} S_{episodic} \text{ Write} \xrightarrow{\text{Phase 4: Consolidate}} S_{semantic} \text{ Promotion}$$

1. **Phase 1: Structure-Matched Parsing**: Parses instructional text into entities, predicates, and constraints via COMPOSE operators.
2. **Phase 2: Invariant Audit**: Audits extracted constraints against existing $S_{invariants}$. If a contradiction is detected, triggers `CLARIFICATION_REQUIRED` (§8).
3. **Phase 3: Primary Entry Write**: Writes factual entries unconditionally to $S_{episodic}$ per SOS-001 Section 4 discipline.
4. **Phase 4: Micro-Replay & Promotion**: Performs 5-step local micro-replay (EXP-022) and schedules offline mentor promotion enforcing CPA-001 INV-1.

- **Epistemic Status**: **Reasoned Hypothesis** (Synthesized from CPA-001 and EXP-025).

## 6. Knowledge Validation Pipeline

Before candidate knowledge $\mathcal{K}_{cand}$ is promoted from $S_{episodic}$ into $S_{semantic}$, it must pass three validation gates:

```
[Candidate Knowledge K_cand]
             |
             v
 [Gate 1: Invariant Audit] ------ (Fails) ----> [Log Contradiction & Request Clarification]
             | (Passes)
             v
 [Gate 2: Verification Tasks] ---- (Fails) ----> [Trigger Local Micro-Replay (k=5)]
             | (Passes)
             v
 [Gate 3: Entropy Boundary] ------ (H >= 1.0) --> [Retain in S_episodic]
             | (H < 1.0)
             v
 [Promote to S_semantic (INV-1)]
```

- **Epistemic Status**: **Reasoned Hypothesis** (Derived from EXP-009 knowledge boundary & EXP-025).

## 7. Understanding Verification Protocol

To verify that genuine understanding has occurred (rather than verbatim memorization), ACA executes a 4-stage verification protocol:

1. **Paraphrase & Reconstruction Protocol**: Re-synthesizes the explanation using canonical primitive symbols. Evaluates if structural content is preserved under token variation.
2. **Novel Scenario Transfer Protocol**: Evaluates performance on unseen verification tasks $\mathcal{T}_{unseen}$ (e.g. SCAN `addprim_jump` split).
3. **Counterfactual Perturbation Protocol**: Alters non-essential entity properties and verifies that causal mechanisms predict correct state transitions.
4. **Boundary Falsification Protocol**: Presents counterexamples $\mathcal{C}_{false}$ and verifies that the system rejects them ($H \ge 1.5$ nats).

- **Epistemic Status**: **Reasoned Hypothesis** (Derived from EXP-020 SCAN methodology).

## 8. Misunderstanding Representation

Misunderstanding is NOT a binary error code; it is represented as four explicit internal cognitive states:

| Internal Cognitive State | Entropy Signal ($H$) | Verification Task Result | Action / Mentor Trigger | Epistemic Status |
|---|---|---|---|---|
| `UNDERSTOOD` | $H < 0.5$ nats | 100% Pass across $\mathcal{T}_{verif}$ | Promote knowledge to $S_{semantic}$ (INV-1) | **Validated** |
| `PARTIALLY_UNDERSTOOD` | $0.5 \le H < 1.5$ nats | Partial Pass ($50\%-99\%$) | Trigger 5-step local micro-replay ($k=5$) | **Validated** |
| `NOT_UNDERSTOOD` | $H \ge 1.5$ nats | Failure ($< 50\%$) | Retain in $S_{episodic}$; request re-teaching | **Validated** |
| `CLARIFICATION_REQUIRED` | Contradiction | Invariant Audit Failure | Generate targeted clarification query (§10) | **Reasoned Hypothesis** |

- **Epistemic Status**: **Validated** (Entropy signals validated by EXP-001, EXP-009, SIP-001).

## 9. Mentor–Student Interaction Protocol

Communication between the Mentor and ACA is governed by five formal interaction primitives:

1. `EXPLAIN(Lesson_ID, Payload)`: Mentor provides instructional explanation $\mathcal{E}$.
2. `VERIFY(Lesson_ID, Task_Suite)`: Mentor issues verification tasks $\mathcal{T}_{verif}$.
3. `REPORT_STATE(Lesson_ID, Cognitive_State, Entropy)`: ACA reports internal state (`UNDERSTOOD`, `PARTIALLY_UNDERSTOOD`, etc.).
4. `CLARIFY(Lesson_ID, Missing_Primitive, Conflict_Spec)`: ACA requests specific clarification on missing prerequisites or constraint conflicts.
5. `PROMOTE(Lesson_ID)`: Mentor authorizes permanent weight consolidation into $S_{semantic}$.

- **Epistemic Status**: **Reasoned Hypothesis** (Communication protocol design).

## 10. Clarification Protocol

When `CLARIFICATION_REQUIRED` is triggered, ACA generates a targeted query rather than a generic error:

```
                  [Invariant Audit Contradiction]
                                 |
                                 v
               [Isolate Contradicting Invariant c in S_invariants]
                                 |
                                 v
  [Synthesize Clarification Request: "Explanation E conflicts with Invariant c"]
                                 |
                                 v
                     [Emit CLARIFY Primitive]
```

This prevents silent hallucination or corrupted weight updates in $S_{semantic}$.

- **Epistemic Status**: **Reasoned Hypothesis** (Derived from CTX-001 audit requirements).

## 11. Knowledge Promotion Criteria

Knowledge promotion from $S_{episodic}$ into $S_{semantic}$ must strictly satisfy **CPA-001 Invariant INV-1 (Recency-Promotion Safety)**:

$$\text{Promote}(k) \iff (H(k) < 1.0\text{ nats}) \land \text{Pass}(\mathcal{T}_{verif}) \land (e_{promote}(k) \prec e_{evict}(k))$$

- **Epistemic Status**: **Validated** (Proven by EXP-025 across 5 seeds: 100% recall restored).

## 13. Process Failure Modes

Instruction-based learning introduces three specific learning failure modes:

| Failure Mode | Symbol | Root Mechanism | Countermeasure / Invariant | Epistemic Status |
|---|---|---|---|---|
| **Verbatim Storage Illusion** | FL-1 | System stores raw text in $S_{episodic}$ without extracting constraints into $S_{invariants}$ | Mandatory Novel Scenario Transfer Protocol (§7) | **Reasoned Hypothesis** |
| **Constraint Hallucination** | FL-2 | System over-generalizes an invariant from insufficient positive examples | Mandatory Boundary Falsification Protocol (§7) | **Reasoned Hypothesis** |
| **Premature Promotion** | FL-3 | Unverified or high-entropy facts promoted to $S_{semantic}$ | Strict CPA-001 INV-1 Enforcement ($H < 1.0$ nats) | **Validated** (EXP-025) |

## 14. Experimental Roadmap (EXP-026 Design)

**EXP-026: Mentor Instruction vs Next-Token Pretraining Falsification Trial**

- **Primary Question**: Can an ACA model acquire structured domain competence (e.g. SCAN composition + relational recall) purely through mentor-guided instruction ($\le 100$ instructional lessons) faster and with $1,000\times$ fewer samples than a standard Transformer trained via next-token prediction over raw text?
- **Falsification Criterion**: Attempt to falsify the central ACA hypothesis. If the instruction-guided ACA model fails to achieve $\ge 95.0\%$ transfer accuracy on unseen tasks while a pre-trained baseline succeeds, the hypothesis is falsified.
- **Experimental Setup**:
  - *Baseline Model*: CausalTransformerLM trained via next-token prediction over 100,000 raw token sequences.
  - *ACA Model*: ACA v1.0 runtime (`runtime/sip002/`) taught via 50 structured lessons using LRS-001 protocols.
  - *Evaluation*: Measures transfer accuracy, sample efficiency, training steps, and parameter footprint.
