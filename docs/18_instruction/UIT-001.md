# UIT-001: Universal Instruction Taxonomy

**Role note:** Produced under the Chief Systems Engineer role for **UIR-001 ("Universal Instruction Research")**. Following ACA-0's 100% benchmark validation (`docs/17_knowledge/KRS-001.md`, EXP-026), the research program shifts from validating the learner to discovering what can be taught through mentor-guided instruction.

UIT-001 derives the minimal, non-redundant computational taxonomy of teachable knowledge categories, analyzing every category across eight required scientific dimensions.

---

## 1. Executive Summary & Category Reduction

The broad spectrum of instructional knowledge (facts, concepts, rules, procedures, causal models, temporal/spatial knowledge, skills, meta-knowledge) is reduced into **five fundamental computational categories** based on their underlying state substrate mappings ($S_{episodic}, S_{semantic}, S_{invariants}$) and computational functions ($\text{EVALUATE}, \text{COMPOSE}, \text{CPA-001}, \text{KRS-001}$):

```
+-------------------------------------------------------------------------------+
|                       UNIVERSAL INSTRUCTION TAXONOMY                          |
+-------------------------------------------------------------------------------+
| 1. Factual-Relational   | State Assertions (s --p--> o) in S_episodic/KRS-001  |
| 2. Constraint-Rule      | Universal Implications forall x (P => Q) in S_invariants|
| 3. Procedural-Algorithm | Transformation Sequences (S_0 -> S_1 -> ...) COMPOSE  |
| 4. Causal-Systemic      | Transition Models & Counterfactual State Copies S'    |
| 5. Meta-Cognitive       | Entropy Signals H & Cognitive Self-States            |
+-------------------------------------------------------------------------------+
```

## 2. Category 1: Factual-Relational Knowledge (State Assertions)

### 2.1 Computational Definition
Grounding of specific state triples $(s, p, o) \in \mathcal{E}_R$ binding entity nodes $s, o \in \mathcal{V}_E$ via a directional predicate $p$.
$$\mathcal{K}_{fact} = \{ (s_i, p_i, o_i) \mid s_i, o_i \in \mathcal{V}_E \}$$
- **Epistemic Status**: **Validated** (EXP-001, EXP-022, EXP-026 Stage 1).

### 2.2 Minimal Lesson Structure
$$\mathcal{L}_{fact} = \langle \text{"Entity X is a Y"}, \text{"Entity X has property Z"} \rangle$$

### 2.3 Required Prerequisite Knowledge
Symbolic grounding of entities $s$ and $o$ in entity store $\mathcal{V}_E$.

### 2.4 Internal Knowledge Representation
Grounded triples in $S_{episodic}$ primary entries and KRS-001 relation edges $\mathcal{E}_R$.

### 2.5 Verification Protocol
Direct Lookup & Proof Trace Protocol: Query $(s, p, o) \to \text{YES/NO}$ with proof trace.

### 2.6 Failure Modes
- *FL-1a (Unbound Symbol)*: Entity $s$ not recognized in $\mathcal{V}_E$.
- *FL-1b (Recency Eviction PM-1)*: Fact evicted from $S_{episodic}$ prior to $S_{semantic}$ consolidation.

### 2.7 Transfer Benchmarks
Category membership transfer (e.g., "Whales are mammals").

### 2.8 Clarification Strategy
Emit `CLARIFICATION_REQUIRED` requesting category assignment for $s$.

## 3. Category 2: Constraint-Rule Knowledge (Invariants & Universal Implications)

### 3.1 Computational Definition
Universally quantified logical implications and boundary invariants enforced in $S_{invariants}$:
$$c = \forall x \left( P_{cond}(x, T_{cond}) \implies P_{impl}(x, T_{impl}) \right)$$
- **Epistemic Status**: **Validated** (EXP-025, EXP-026 Stage 2 & 3).

### 3.2 Minimal Lesson Structure
$$\mathcal{L}_{rule} = \langle \text{"All X [condition] Y"}, \text{"No X can [violation] Y"} \rangle$$

### 3.3 Required Prerequisite Knowledge
Condition category symbol $T_{cond}$ must exist in $\mathcal{V}_E$.

### 3.4 Internal Knowledge Representation
Rule objects stored in $S_{invariants}$ ($\mathcal{C}_I$).

### 3.5 Verification Protocol
Invariant Audit Protocol & Non-Verbatim Proof Unrolling: Evaluates if $\forall x \in T_{cond}$, $P_{impl}(x)$ holds.

### 3.6 Failure Modes
- *FL-2a (Ungrounded Invariant)*: Rule condition target $T_{cond}$ missing from $\mathcal{V}_E$.
- *FL-2b (Constraint Hallucination)*: Over-generalizing an invariant from insufficient positive examples.

### 3.7 Transfer Benchmarks
Binding rule $c$ to novel entity instance $x_{new} \in T_{cond}$ (e.g. EXP-026 Stage 3 Dolphin transfer).

### 3.8 Clarification Strategy
Emit `CLARIFICATION_REQUIRED` identifying missing prerequisite category $T_{cond}$.

## 4. Category 3: Procedural-Algorithmic Knowledge (Transformation Sequences & State Operators)

### 4.1 Computational Definition
Sequential, step-by-step state transformation operators that map initial state $S_0$ to target state $S_k$:
$$\mathcal{P} = [ op_1, op_2, \dots, op_k ] \quad \text{such that} \quad S_0 \xrightarrow{op_1} S_1 \xrightarrow{op_2} \dots \xrightarrow{op_k} S_k$$
- **Epistemic Status**: **Validated** (EXP-002, EXP-020 SCAN pathway).

### 4.2 Minimal Lesson Structure
$$\mathcal{L}_{proc} = \langle \text{Input Pattern}, \text{Ordered Step Operators}, \text{Expected Output Pattern} \rangle$$

### 4.3 Required Prerequisite Knowledge
Primitive action mappings in COMPOSE lookup table (RC-01).

### 4.4 Internal Knowledge Representation
Structure-matched slot sequence templates and COMPOSE parse tables.

### 4.5 Verification Protocol
Execution Trace Protocol: Run input tokens through COMPOSE, compare output sequence against target actions.

### 4.6 Failure Modes
- *FL-3a (Structural Depth Limit)*: Nesting recursion depth $\ge 3$ (EXP-023 step-function collapse).
- *FL-3b (Operator Dislocation)*: Step order inverted or omitted.

### 4.7 Transfer Benchmarks
Length generalization split (e.g., SCAN `addprim_jump` split).

### 4.8 Clarification Strategy
Request step-by-step operator breakdown for unrecognized sub-commands.

## 5. Category 4: Causal-Systemic Knowledge (State Transition Models & Structural Dynamics)

### 5.1 Computational Definition
Causal state graphs $\mathcal{G}_{causal} = (V_{state}, E_{cause})$ predicting state transitions and counterfactual outcomes under premise mutation ($S \to S'_{counter}$).
$$\text{CausalModel}: (S, \Delta P) \mapsto S'$$
- **Epistemic Status**: **Validated** (EXP-026 Stage 4 Counterfactual Simulation).

### 5.2 Minimal Lesson Structure
$$\mathcal{L}_{causal} = \langle \text{Initial State S}, \text{Intervention } \Delta P, \text{Target State S'} \rangle$$

### 5.3 Required Prerequisite Knowledge
Category rules in $S_{invariants}$ and entity properties in $\mathcal{V}_E$.

### 5.4 Internal Knowledge Representation
State mutation solvers and counterfactual state copy generators ($S'_{counter}$ in KRS-001 §4).

### 5.5 Verification Protocol
Counterfactual Perturbation Protocol: Mutate premise $(s, \text{is\_a}, Y) \to (s, \text{is\_a}, Z)$, verify prediction changes correctly.

### 5.6 Failure Modes
- *FL-4a (Causal Leakage)*: Failing to clear derived facts during counterfactual state copy creation.
- *FL-4b (Spurious Correlation)*: Confounding correlation with causal necessity.

### 5.7 Transfer Benchmarks
Counterfactual state prediction on altered domain premises (EXP-026 Stage 4).

### 5.8 Clarification Strategy
Request clarification on intervention mechanism when state transition is ambiguous.

## 6. Category 5: Meta-Cognitive Knowledge (Epistemic Self-State & Uncertainty Calibration)

### 6.1 Computational Definition
Internal monitoring of epistemic confidence, entropy signals $H(\text{EVALUATE-LOCAL})$, and missing knowledge detection:
$$\text{SelfState} = \begin{cases} 
\text{UNDERSTOOD} & H < 0.5 \text{ nats} \\
\text{PARTIALLY\_UNDERSTOOD} & 0.5 \le H < 1.5 \text{ nats} \\
\text{NOT\_UNDERSTOOD} & H \ge 1.5 \text{ nats} \\
\text{CLARIFICATION\_REQUIRED} & \text{Missing Symbol / Invariant Contradiction}
\end{cases}$$
- **Epistemic Status**: **Validated** (EXP-009, SIP-001, LRS-001 §8, EXP-026 Stage 5).

### 6.2 Minimal Lesson Structure
$$\mathcal{L}_{meta} = \langle \text{Confidence Threshold Criteria}, \text{Self-Correction Triggers} \rangle$$

### 6.3 Required Prerequisite Knowledge
EVALUATE-LOCAL entropy signal calculation mechanism (SR-01).

### 6.4 Internal Knowledge Representation
`EpisodicMemory.unconditional_write("unknown", ...)` entries and `EpisodeLog` anomaly flags.

### 6.5 Verification Protocol
Boundary Detection Protocol: Query unknown item, verify system emits `CLARIFICATION_REQUIRED` without hallucination.

### 6.6 Failure Modes
- *FL-5a (Overconfidence / Hallucination)*: Returning low entropy for un-taught or contradictory inputs.
- *FL-5b (Underconfidence)*: Retaining high entropy for fully taught, verified facts.

### 6.7 Transfer Benchmarks
Zero-shot unknown detection on out-of-vocabulary entities (EXP-026 Stage 5).

### 6.8 Clarification Strategy
Synthesize targeted, entity-specific query: `"I do not know what kind of entity X is..."`.
