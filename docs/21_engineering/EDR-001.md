## 1. Executive Summary
The foundational research phase of ACA is complete. The system has progressed through multiple theoretical iterations and adversarial falsification trials. EDR-001 synthesizes all experimental evidence, theoretical specifications (LRS-001, KRS-001, CUR-001, KGP-001), and validated constraints (CPA-001, SOS-001) into a single integration blueprint for **ACA-1**. 

The primary engineering mandate for ACA-1 is not to maximize capability, but to construct the smallest possible runtime capable of exercising the complete cognitive loop (Instruction $\to$ Understanding $\to$ Governance $\to$ Continual Memory $\to$ Reasoning) without violating any empirically discovered boundaries.

## 3. Integration Analysis
ACA-1 will be built as an evolution of the `runtime/sip002/` and `runtime/aca0/` codebases.

### 3.1. What Fits ACA v1.0 Unchanged
- **$S_{episodic}$ Capacity Limits**: The hard capacity limit $C$ and FIFO eviction trigger.
- **COMPOSE Recursion Constraint**: Bounded to depth $\le 2$ (from EXP-023 — **unverified, see Section 7**; treat as a plausible working assumption pending re-verification, not an established boundary).
- **EVALUATE-LOCAL Entropy Gating**: The 1.5-nat confidence threshold for recall.

### 3.2. What Requires Implementation Only
- **Curriculum Parsing**: Reading prerequisite edges ($E_{prereq}$) from lessons as defined in CUR-001.
- **KRS-001 Graph Migrations**: Porting the `aca0` tuple structure $\langle \mathcal{V}_E, \mathcal{E}_R, \mathcal{C}_I \rangle$ into the main semantic backbone.

### 3.3. What Requires Architectural Modification
- **The Governance Split**: `runtime.py` must be structurally split. The existing monolith loop (`Lesson` $\to$ `Update Weights`) must be broken into a synchronous pipeline: `Acquire (LRS)` $\to$ `Propose` $\to$ `Audit (KGP)` $\to$ `Consolidate`.
- **The Provisional Replay Buffer**: To satisfy KGP-001 and prevent EXP-031's catastrophic forgetting, $S_{semantic}$ updates must sample from a historical buffer rather than applying isolated gradient steps online.
- **Explicit Invariant Audit**: Disjointness constraints must be actively queried *before* a lesson enters $S_{episodic}$.

### 3.4. What Should Not Yet Be Implemented
- **Automated Source Reliability**: Discovering $R_{mentor}$ autonomously. For ACA-1, $R$ will be manually injected as a fixed parameter.
- **Offline Mentor Generation**: The SIP-002 offline curriculum generation module should be temporarily suspended. ACA-1 will focus strictly on synchronous mentor instruction to isolate governance mechanisms.

## 4. ACA-1 Integration Architecture (The Minimal Runtime)
ACA-1 will implement the following strict sequential pipeline per episode:

1. **Ingress**: The Mentor provides an instruction $I$ and Source Reliability $R_{mentor}$.
2. **Acquisition (LRS-001)**: The Learner parses $I$ into a `PROVISIONAL` KRS-001 graph $K_{new}$.
3. **Audit (KGP-001)**: The Governance module queries $S_{invariants}$ for contradictions against $K_{new}$.
   - *If Contradiction (Equal Trust)*: Halt and `CLARIFY`.
   - *If Contradiction (Low Trust)*: `DEPRECATE` and log.
   - *If Safe*: `PROPOSE` $K_{new}$.
4. **Episodic Write (SOS-001)**: $K_{new}$ is unconditionally appended to $S_{episodic}$.
5. **Consolidation (CPA-001 / KGP-001)**: If a pre-eviction trigger (INV-1) fires, Governance samples the Replay Buffer and performs a batched gradient update to $S_{semantic}$.
6. **Reasoning (RC-01)**: All downstream deductions operate *only* on `CONSOLIDATED` or `VALIDATED` state.

## 5. Engineering Risk Assessment
| Risk | Description | Mitigation Strategy |
| :--- | :--- | :--- |
| **Catastrophic Forgetting** | Even with a replay buffer, rapid sequential curriculum shifts might still overwrite $S_{semantic}$ representations if sampling is skewed. | Implement strict $\epsilon$-threshold monitoring during `CONSOLIDATE`. Revert if historical recall drops. |
| **Invariant Explosion** | Checking $S_{invariants}$ against the global graph for every new edge becomes computationally intractable at scale $N \gg C$. | Bound the `AUDIT` scope to the local 1-hop conceptual neighborhood of the parsed entities. |
| **Replay Buffer Stagnation**| The buffer may become saturated with redundant facts, limiting diversity during consolidation. | Implement a diversity-aware stratified sampling mechanism inside the `CONSOLIDATE` operation. |

## 6. Minimal Implementation Roadmap
The strict, sequential engineering roadmap for building ACA-1:

- **Phase 1 (Substrates)**: Merge the `aca0` KRS representation with the `sip002` memory substrates into a new `runtime/aca1/` module. **Not blocked** — this is genuine engineering integration of already-validated components (KRS-001/EXP-026, SOS-001/EXP-019/022).
- **Phase 2 (Governance Stubs)**: Implement the `PROVISIONAL` state wrapper and a baseline `AUDIT` function that checks for exact contradictions. **Not blocked** — grounded in EXP-027/031, which are independently verified (see Section 7).
- **Phase 3 (Replay Buffer)**: Implement the historical sampling mechanism to replace SIP-002's isolated pre-eviction hooks. **BLOCKED.** The premise ("replace hooks that don't work with a buffer that does") assumes EXP-025 showed the hooks failing in a specific, understood way and that a buffer is the fix — neither is currently established. Do not implement until EXP-023/024 are re-verified and a real candidate fix is found and falsification-tested per DEC-006.
- **Phase 4 (Integration Pipeline)**: Wire the `Learner` $\to$ `Governance` $\to$ `Memory` pipeline together. **Partially blocked** — the Learner/Governance wiring is fine; do not wire in Phase 3's unvalidated consolidation step.
- **Phase 5 (Validation)**: Execute EXP-027 (Contradictory Knowledge) and EXP-031 (1,000-Lesson Continual) protocols against ACA-1 to prove the theoretical KGP-001 fixes work in practice. **Not blocked in principle** — but meaningless to run against a Phase 3 that hasn't been validated as a real fix yet; sequence after Phase 3 is actually resolved.

## 7. Correction (Appended 2026-07-30, Not Edited Into Prior Sections)

This document's Section 2 originally tagged "Recency-Promotion Safety (INV-1)" as `[Experimentally Validated]`, citing `docs/15_process/CPA-001.md` and EXP-025. This document's own Section 2 states the correct governing rule: *"No [Reasoned Hypothesis] may be silently promoted to a [Validated] mechanism during ACA-1 implementation."* The INV-1 row violated that rule at the point this document was written — corrected here, not smoothed over, per the same rule.

**Consequence:** Phase 3 of Section 6 (the Replay Buffer, "to replace SIP-002's isolated pre-eviction hooks") is not ready for implementation — the premise that a buffer would fix what hooks don't has not been tested, because it was never established that the hooks fail in the specific, understood way EXP-025 claimed. The COMPOSE recursion-depth-$\le 2$ constraint (Section 3.1) rests on the similarly-unverified EXP-023 and should be treated as a working assumption, not an established boundary, until re-verified.

**What is not affected:** the Governance (KGP-001) and Learning (LRS-001/KRS-001) dependencies in Section 2 rest on EXP-026, EXP-027, and EXP-031, which were independently checked (real per-seed data, real large trace logs, working non-trivial code) and remain genuinely validated. Phases 1, 2, and most of 4 in Section 6 can proceed on that basis.
