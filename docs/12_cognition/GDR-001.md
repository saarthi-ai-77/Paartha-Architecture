## 1. Research Question

### 1.1 The Core Problem
Modern artificial intelligence equates "reasoning" with autoregressive token generation conditioned on hundreds of billions of pretrained parameters. In frontier large language models (LLMs), world knowledge, grammatical competence, problem-solving heuristics, tool invocation, and self-monitoring are entrained into a monolithic parameter vector through trillions of tokens of web-scale self-supervised learning.

Paartha deliberately rejects massive monolithic pretraining as the primary pathway to adaptive intelligence. Previous Paartha research has concentrated on:
* Structurally isolated computational substrates ($S_{episodic}, S_{semantic}, S_{invariants}$ in ACA v1.0).
* Working memory retention under sequential pressure (CTX-001, EXP-019).
* Modular capability acquisition from external mentors (LRS-001, EXP-033).
* Verified invariant compilation and execution libraries ($\mathcal{L}$).

However, possessing a structured memory and a library of verified computational capabilities does **not** constitute an intelligent, autonomous problem-solving agent. If an agent has a set of verified computational primitives (e.g., sorting, graph search, numerical integration, text parsing) and a multi-substrate memory, it remains inert until something decides:
1. What the user or environment actually wants.
2. Which sequence, composition, or synthesis of capabilities can satisfy that intent.
3. How to execute the computation step-by-step across disparate substrates.
4. How to verify that the intermediate and final outputs satisfy the goal invariants.
5. How to diagnose and recover if an execution step fails or an invariant is violated.
6. When the goal is met and computation must halt.
7. How to translate the internal computational result back into human-communicable output.

This document investigates the foundational question:

> **If Paartha does not rely on massive pretraining, how can it accept an arbitrary goal or natural-language request, determine what needs to be done, construct or retrieve the necessary computation, execute it, verify the result, revise when necessary, and communicate the result appropriately?**

### 1.2 Motivating Target Scenarios
To ensure the investigation remains grounded and resistant to hand-waving abstraction, we evaluate any candidate reasoning mechanism against four concrete archetypes:
1. **Algorithmic Construction:** *"Write a Python program that takes an undirected graph and finds the minimal cut without using external graph libraries."* (Requires exact algorithmic synthesis, syntax/type invariants, edge-case verification, iterative execution/testing).
2. **Constrained Natural-Language Pragmatics:** *"Write an email asking my professor for a 3-day extension on my machine learning project due to illness, balancing professional deference with clear factual claims."* (Requires social/relational model, goal state satisfying multiple tone and factual constraints, communicative surface realization).
3. **Diagnostic Reasoning & Debugging:** *"Why is this distributed pipeline deadlocking intermittently under 10k QPS?"* (Requires hypothesis generation, abductive reasoning, causal tracing across execution traces, counterfactual testing, selective verification).
4. **Information Synthesis & Research:** *"Research whether topological data analysis has yielded verifiable improvements in genomic cancer classification."* (Requires open-ended search, evidence extraction, relevance evaluation, contradiction detection, source arbitration, epistemic calibration).

## 2. Why Existing Paartha Research Is Insufficient by Itself

Previous Paartha research has made rigorous progress on memory, capability storage, and parameter isolation. However, an adversarial audit reveals that the current repository contains **no architecture for goal-directed orchestration**.

```
+-------------------------------------------------------------------------+
|                       THE PAARTHA ORCHESTRATION GAP                     |
+-------------------------------------------------------------------------+
|  WHAT PAARTHA CURRENTLY HAS:                                            |
|  * Substrates: S_episodic (K-V store), S_semantic (weights),            |
|               S_invariants (rules), S_working (reserved partition)      |
|  * Primitives: Verified computational modules in Library L               |
|  * Functions: EVALUATE, SELECT, UPDATE, COMPOSE                         |
|  * Learning: Mentor guidance, single-capability acquisition             |
+-------------------------------------------------------------------------+
                                    ||
                                    ||  ??? (WHO ASSEMBLES, PLANS,
                                    ||       VERIFIES, AND RECOVERS?)
                                    \/
+-------------------------------------------------------------------------+
|  WHAT AN ARBITRARY USER GOAL REQUIRES:                                  |
|  "Debug this pipeline" / "Write an extension email" / "Synthesize code" |
|  * Intent Ingestion & Goal Predicate Formulation                        |
|  * Multi-step Planning & Hypothesis Generation                          |
|  * Runtime Execution & Cross-Substrate State Binding                    |
|  * Independent Ground-Truth Invariant Verification                      |
|  * Failure Attribution & Backtracking                                   |
|  * Communicative Surface Realization                                    |
+-------------------------------------------------------------------------+
```

### 2.1 The Competence vs. Orchestration Fallacy
* `ACA v1.0` defines four computational functions: `EVALUATE`, `SELECT`, `UPDATE`, and `COMPOSE`. While theoretically expressive, these functions are **operators**, not **controllers**. Saying an agent reasons by running `EVALUATE` and `SELECT` is equivalent to saying a computer calculates by executing `NAND` gates. It leaves unanswered: *which circuit is assembled, what clock drives it, and what program counter tracks progress?*
* `CTX-001` and `EXP-019` established that conversation context and working memory can be stored in a reserved partition of $S_{episodic}$ written unconditionally. This provides a *scratchpad*, but a scratchpad does not write itself, inspect itself, or know what computation to run next.
* `EXP-033` and `RES-ONT-006` investigated isolating learned capabilities into modular parameter containers or IR blocks. But a library of 10,000 verified functions cannot solve a novel problem without an orchestration engine that can formulate search queries, compose pipelines, bind intermediate state variables, and handle exceptions.

### 2.2 The Collapse of the "Language is Thinking" Assumption
In monolithic LLMs, language generation and computation are indistinguishable: next-token prediction performs parsing, world simulation, deduction, calculation, and output formatting in a single autoregressive stream.
* When this succeeds, it creates the illusion of seamless general intelligence.
* When it fails, it exhibits catastrophic hallucinations, subtle logic bugs, inability to maintain formal invariants, and reasoning decay on out-of-distribution graph/arithmetic structures (Dziri et al., 2023; Mirzadeh et al., 2024).

Because Paartha does not train a 100-billion-parameter foundation model on the entire internet, **it cannot rely on emergent latent reasoning embedded in language weights**. Paartha must explicitly decouple:
$$\text{Knowing Something} \neq \text{Being Able to Compute} \neq \text{Knowing Which Computation to Run} \neq \text{Executing} \neq \text{Verifying} \neq \text{Communicating}$$

## 3. Terminology and Formal Definitions

To prevent semantic drift, we formally define the core objects of goal-directed cognition.

```
       Natural Language Request
                  │
                  ▼
         ┌─────────────────┐
         │ Goal Ingestion  │ ──> Identifies Target Predicate Φ(s) and Constraints C
         └─────────────────┘
                  │
                  ▼
         ┌─────────────────┐
         │  Task Framing   │ ──> Constructs Initial Task T = (G, s_0, C)
         └─────────────────┘
                  │
                  ▼
         ┌─────────────────┐
         │   Plan Search   │ <───┐
         │   / Synthesis   │     │ (Recovery / Backtracking Loop)
         └─────────────────┘     │
                  │              │
             Plan π (DAG)        │
                  │              │
                  ▼              │
         ┌─────────────────┐     │
   ┌───> │ Execution Engine│     │
   │     └─────────────────┘     │
   │              │              │
   │       Next State s'         │
   │              ▼              │
   │     ┌─────────────────┐     │
   │     │  Verification   │ ──> FAIL: Attribute Failure & Recalculate
   │     │  (Invariants)   │
   │     └─────────────────┘
   │              │ PASS (Terminal Φ(s*) = 1)
   │              ▼
   │     ┌─────────────────┐
   └──── │ Surface Realizer│ ──> External Output (Language / Code / Artifact)
(Step    └─────────────────┘
 Loop)
```

### 3.1 Core Mathematical Objects
1. **Goal ($G \in \mathcal{G}$):** A formal declaration of an intended terminal state, represented as a satisfaction predicate $\Phi: \mathcal{S} \to \{0, 1\}$ over state space $\mathcal{S}$, paired with an optimization utility function $U: \mathcal{S} \to \mathbb{R}$.
2. **Task ($T \in \mathcal{T}$):** A grounded instantiation of a goal: $T = (G, s_0, \mathcal{C}, \mathcal{B})$, where $s_0 \in \mathcal{S}$ is the initial working state, $\mathcal{C} = \{c_1, \dots, c_m\}$ is a set of hard invariant constraints (safety, structural, semantic), and $\mathcal{B} = (T_{max}, \text{FLOP}_{max}, \text{Mem}_{max})$ is the compute budget.
3. **Plan ($\pi \in \Pi$):** A computational directed acyclic graph (DAG) or structured control program $\pi = (\mathcal{V}_\pi, \mathcal{E}_\pi)$, where vertices $v_i \in \mathcal{V}_\pi$ represent discrete computational operators, and edges $e_{ij} \in \mathcal{E}_\pi$ define state and data-flow bindings.
4. **Capability / Primitive ($P \in \mathcal{L}$):** An independently verified, reusable operator $P: \mathcal{X} \to \mathcal{Y}$ characterized by a typed signature, explicit preconditions $\text{Pre}(P)$, postconditions $\text{Post}(P)$, and invariant guarantees $\text{Inv}(P)$. Primitives may be symbolic (e.g., deterministic Python AST transform) or neural (e.g., specialized invariant embedding mapping).
5. **Cognitive State ($s \in \mathcal{S}$):** The bounded internal state at step $t$, partitioned into working memory, environmental bindings, active hypotheses, and execution history:
   $$s_t = \langle s_{working}, s_{bindings}, s_{hypotheses}, s_{trace} \rangle$$
6. **Execution ($\tau$):** The deterministic runtime transition operator:
   $$\tau: \mathcal{S} \times \mathcal{L} \to \mathcal{S}'$$
   which applies primitive $P$ to state $s$ under variable binding $\theta$, yielding next state $s'$.
7. **Verification ($V$):** An independent, non-generative decision procedure:
   $$V: \mathcal{G} \times \mathcal{S} \times \mathcal{C} \to \{\text{PASS}, \text{FAIL}(\delta), \text{INCONCLUSIVE}\}$$
   where $\delta$ is a diagnostic error record indicating violated invariants or distance from target predicate $\Phi$.
8. **Recovery ($\mathcal{R}$):** The repair function that updates the plan or state upon verification failure:
   $$\mathcal{R}: \Pi \times s \times \delta \to \Pi'$$
   capable of local parameter patching, sub-DAG replacement, or backtracking.
9. **Communication ($\kappa$):** The interface projection function:
   $$\kappa: \mathcal{S} \times \mathcal{G} \to \Omega^*$$
   which translates internal structured state and execution traces into external symbolic sequences (natural language tokens, code files, or protocol payloads) tailored to an external interlocutor.

## 4. Literature and Research Landscape

To establish how an AI system can reason without massive pretraining, we survey the seven major paradigms in computation, planning, and cognitive science.

```
+------------------------------------------------------------------------------------+
| PARADIGM SPECTRUM: KNOWLEDGE SOURCE VS. INFERENCE COMPUTE                          |
+------------------------------------------------------------------------------------+
|                                                                                    |
|  [Extensive Pretraining / Weak Search]         [Zero Pretraining / Strong Search]  |
|  Monolithic LLMs (GPT-4, Llama)                Classical Planning (Fast Downward)  |
|         │                                                       │                  |
|         ▼                                                       ▼                  |
|  Prompted LLM Agents (ReAct)                   Program Synthesis (FlashFill, Sketch)|
|         │                                                       │                  |
|         ▼                                                       ▼                  |
|  Test-Time Compute Search (o1, MCTS)           Cognitive Architectures (ACT-R, SOAR)|
|         │                                                       │                  |
|         └───────────────────────┬───────────────────────────────┘                  |
|                                 ▼                                                  |
|                   Neurosymbolic Hybrid Architectures                               |
|                     (DreamCoder, AlphaGo, JEPA)                                    |
|                                                                                    |
+------------------------------------------------------------------------------------+
```

### 4.1 Classical Symbolic Planning (STRIPS, PDDL, HTN)
* **Mechanisms:** Fikes & Nilsson (1971) STRIPS; McDermott et al. (1998) PDDL; Nau et al. (2003) Hierarchical Task Networks (HTN); Helmert (2006) Fast Downward.
* **Operation:** Given a formal domain definition (actions with typed pre/postconditions), an initial state $s_0$, and a goal formula $G$, classical planners use domain-independent heuristics ($h^+$, $h^{FF}$, causal graphs) with $A^*$ search to find a provably valid action sequence.
* **Strengths:** 100% sound; zero hallucination; transparent verification; no pretraining required.
* **Fatal Flaw for Paartha:** The **Knowledge Acquisition Bottleneck**. The real world cannot be hand-coded into closed PDDL predicates. Classical planning fails the moment a goal is stated in ambiguous natural language or involves open-world perceptual state.

### 4.2 Program Synthesis & Inductive Logic Programming (ILP)
* **Mechanisms:** Gulwani (2011) FlashFill; Solar-Lezama (2008) Sketching; Muggleton (1991) ILP; Ellis et al. (2021) DreamCoder.
* **Operation:** Formulates reasoning as program search through a Domain Specific Language (DSL). Given input-output examples or an acceptance predicate, it explores syntax trees using enumerative search, constraint satisfaction (SMT solvers), or learned recognition networks that bias search order.
* **Strengths:** Produces exact, verifiable, modular, and interpretable computational programs. DreamCoder demonstrated bootstrapping primitive libraries via "wake-sleep" compression without foundation pretraining.
* **Limitation for Paartha:** Combinatorial explosion. Program synthesis works brilliantly in tightly constrained, DSL-bounded micro-worlds (list transformations, regex, basic graphics), but collapses in open-ended unstructured reasoning (e.g., interpersonal communication or ambiguous architectural debugging).

### 4.3 Neurosymbolic & Modular Systems
* **Mechanisms:** Andreas et al. (2016) Neural Module Networks; Yi et al. (2018) Neural-Symbolic VQA; Marcus (2020); Garcez et al. (2019).
* **Operation:** Decomposes a query into a symbolic execution graph (e.g., parse question $\to$ modular AST $\to$ dynamic assembly of specialized neural layers).
* **Strengths:** Clean separation between composition logic (symbolic parser) and continuous execution (neural perception modules). Robust out-of-distribution composition.
* **Limitation for Paartha:** Historically relied on fixed, hand-designed module repertoires and rigid grammars; struggle to invent new modules or adapt when task semantics exceed the module vocabulary.

### 4.4 Test-Time Compute & Heuristic Tree Search
* **Mechanisms:** Silver et al. (2016) AlphaGo; Li et al. (2022) AlphaCode; OpenAI (2024) o1; Snell et al. (2024) Scaling LLM Test-Time Compute.
* **Operation:** Trades pretraining compute for inference-time compute. Uses an evaluation/value network to guide Monte Carlo Tree Search (MCTS), beam search, or revision loops over candidate steps.
* **Strengths:** Demonstrates super-human reasoning in bounded, verifiable environments (Go, Chess, competitive programming) where an automated checker exists.
* **Key Finding for Paartha:** **Compute at inference time can substitute for parameter scale.** A compact model equipped with tree search and a verifier routinely outperforms a 10x larger model evaluated greedily.

### 4.5 LLM Agents & Verbal Reflection Loops
* **Mechanisms:** Yao et al. (2022) ReAct; Shinn et al. (2023) Reflexion; Schick et al. (2023) Toolformer; Wang et al. (2023) Voyager.
* **Operation:** Uses an autoregressive LLM to interleave reasoning traces, environment actions (tool API calls), and verbal self-reflections ("Observation: Error. Thought: I should try parameter Y instead.").
* **Pathologies & Falsifications:**
  * **Verbal Reflection Illusion:** Huang et al. (2023) demonstrated that LLMs cannot reliably self-correct reasoning errors without external ground truth; "self-reflection" often causes the model to abandon correct solutions or hallucinate fixes.
  * **Context Saturation & Drift:** As conversation history grows, token attention degrades, causing goal drift and catastrophic forgets of initial constraints (EXP-019/CTX-001).
  * **Fragile Subgraph Matching:** Dziri et al. (2023) proved LLMs do not execute algorithms; they perform pattern matching against training trajectories. When multi-step composition requires intermediate state tracking outside the training manifold, accuracy collapses to near zero.

### 4.6 Classical Cognitive Architectures
* **Mechanisms:** Newell (1990) & Laird (2012) SOAR; Anderson (1993) ACT-R; Sun (2002) CLARION.
* **Operation:** Founded on production rule systems operating over distinct working and long-term memory stores. Execution proceeds via fixed cyclic phases: `Elaboration → Propose Operators → Evaluate/Select Operator → Apply Operator → Resolve Impasses (Subgoaling)`.
* **Strengths:** Rigorous, decades-validated cognitive taxonomy; explicit goal hierarchies; native handling of impasses (subgoal creation when no rule matches).
* **Limitation for Paartha:** Production rules are brittle and discrete. They lack natural mechanisms for continuous state embedding, fuzzy semantic matching, and gradient-based adaptation.

### 4.7 World Models & Self-Supervised Latent Planners
* **Mechanisms:** LeCun (2022) Joint Embedding Predictive Architecture (JEPA); Ha & Schmidhuber (2018) World Models; Hafner et al. (2023) DreamerV3.
* **Operation:** Learns a predictive model of environment dynamics purely in latent representation space: $s_{t+1} = M(s_t, a_t)$. Planning is conducted by optimizing actions against a learned energy function or value head in latent space without decoding to text or pixels.
* **Relevance for Paartha:** Demonstrates that planning can occur in abstract invariant-bounded state spaces rather than token space.

## 6. The Fundamental Decomposition: The Seven Separated Faculties

To build goal-directed reasoning without monolithic pretraining, Paartha must treat the seven cognitive faculties as architecturally isolated, independently testable mechanisms. Conflating them is the fatal design error of LLM-centric systems.

```
+----------------------------------------------------------------------------------------------------+
|                               THE SEVEN SEPARATED FACULTIES                                        |
+----------------------------------------------------------------------------------------------------+
| 1. KNOWING SOMETHING          Declarative storage in S_episodic / S_invariants                     |
|                               (Does the system store the fact / relationship?)                     |
|                                                                                                    |
| 2. BEING ABLE TO COMPUTE      Operational capability in Library L                                  |
|                               (Does an operator exist that can perform the transform?)             |
|                                                                                                    |
| 3. SELECTING COMPUTATION      Goal-directed orchestration                                          |
|                               (Can the system map G -> Plan π without hallucinating?)              |
|                                                                                                    |
| 4. EXECUTING COMPUTATION      State transition engine                                              |
|                               (Applying P(s) -> s' with bounded working memory S_working)          |
|                                                                                                    |
| 5. VERIFYING SUCCESS          Independent invariant auditing                                       |
|                               (Evaluating Φ(s) via non-generative, deterministic tests)             |
|                                                                                                    |
| 6. RECOVERING FROM FAILURE    Attribution & Repair                                                 |
|                               (Isolating failure to plan vs. operator vs. environment)             |
|                                                                                                    |
| 7. COMMUNICATING              Surface realization                                                  |
|                               (Translating internal structured result s* into natural language)    |
+----------------------------------------------------------------------------------------------------+
```

### Faculty 1: Knowing Something (Declarative Storage)
* **What it is:** Static or associative retention of facts, entities, relational graphs, and domain constraints.
* **Where it lives:** $S_{episodic}$ (key-value indexed by entity/schema) and $S_{invariants}$ (formal immutable domain rules).
* **Failure mode:** Factual omission or retrieval miss. *It is not a reasoning failure; it is an information retrieval failure.*

### Faculty 2: Being Able to Compute (Operational Capability)
* **What it is:** The presence of an isolated, verified operator $P \in \mathcal{L}$ that takes typed input $x$ and deterministically or invariantly transforms it to $y$.
* **Where it lives:** The verified primitive library $\mathcal{L}$ (acquired via mentor distillation, EXP-033).
* **Failure mode:** Algorithmic deficiency (e.g., trying to calculate a shortest path when no search primitive exists).

### Faculty 3: Knowing Which Computation to Perform (Strategy Selection & Planning)
* **What it is:** The meta-algorithmic decision that maps task $T = (G, s_0, \mathcal{C})$ into an executable plan $\pi$.
* **How it works:** This is the core cognitive bottleneck. It must determine whether the task can be solved by:
  * *Direct Retrieval:* A compiled routine already exists in $\mathcal{L}$.
  * *Heuristic Decomposition:* Breaking $G$ into known subgoals via Hierarchical Task Reduction.
  * *Constructive Synthesis:* Synthesizing a novel DAG of primitives using bounded search or program sketching.
* **Failure mode:** Plan invalidity, circular dependency, or combinatorial search explosion.

### Faculty 4: Executing Computation (Runtime State Transition)
* **What it is:** Stepping through plan $\pi$, binding input arguments from working state $s_{working}$ to operator $P_i$, and writing outputs back into $s_{working}$.
* **Where it lives:** The Paartha Runtime Environment executing within the reserved partition of $S_{episodic}$ (CTX-001, EXP-019).
* **Failure mode:** Runtime exception, type mismatch, or resource budget exhaustion.

### Faculty 5: Verifying Computation (Independent Invariant Auditing)
* **What it is:** A non-generative checker that determines whether state $s$ satisfies goal predicate $\Phi(s)$ and invariant constraints $\mathcal{C}$.
* **Crucial Architectural Rule:** **The verifier must NOT be the same process that generated the computation.** LLM "self-reflection" fails because the generator's priors infect its evaluation. Verification must be grounded in:
  * Deterministic test assertions (unit tests, typecheckers, SMT solvers).
  * External environment feedback (execution return codes, compiler errors).
  * Independent dual-path invariant checking (e.g., verifying a math problem by numerical substitution or independent constraint satisfaction).
* **Failure mode:** False positive (accepting incorrect state) or uninformative rejection (failing without diagnostic $\delta$).

### Faculty 6: Recovering from Failure (Diagnosis, Backtracking, Replanning)
* **What it is:** When verification returns $\text{FAIL}(\delta)$, the system must perform causal credit assignment:
  * *Case A (Operator failure):* The plan was sound, but primitive $P_k$ failed its postcondition $\to$ retry with alternate primitive $P_k'$.
  * *Case B (Plan failure):* The primitives operated correctly, but the resulting state violates $\Phi$ $\to$ prune plan branch and backtrack in plan search space.
  * *Case C (Prerequisite failure):* An unstated assumption in $s_0$ was false $\to$ generate informational subgoal to query the environment or user.
* **Failure mode:** Infinite repair thrashing, repeating identical failed paths, or hallucinating false repairs.

### Faculty 7: Communicating (Surface Realization)
* **What it is:** Rendering internal structured computational state $s^*$ and execution traces into clear, pragmatic, human-comprehensible natural language or formatted artifacts.
* **Key Insight:** **Language is an output rendering target, not the cognitive workspace.** In human cognition, deep thought is non-verbal (spatial, structural, conceptual); verbalization is an encoding process that occurs when preparing to transmit state to another agent (Levelt, 1989). In Paartha, language generation is performed by a dedicated surface realizer conditioned on verified internal state.
* **Failure mode:** Stylistic misalignment, pragmatic tone failure, or communicative omission. *Crucially, if the computation was verified, the communication cannot hallucinate underlying facts.*

## 7. Open Problems in Pretraining-Free Goal-Directed Reasoning

When monolithic pretraining is removed, five fundamental engineering and theoretical problems emerge that have historically been swept under the rug by foundation models.

```
+----------------------------------------------------------------------------------------+
|                      THE FIVE OPEN PROBLEMS OF PRETRAINING-FREE COGNITION              |
+----------------------------------------------------------------------------------------+
|                                                                                        |
|  1. THE GOAL PARSING & GROUNDING GAP                                                   |
|     How does raw natural language map to formal predicate Phi(s) without 100B params?|
|                                                                                        |
|  2. THE COMPUTATIONAL STRATEGY SELECTION PROBLEM                                       |
|     Algorithm selection under budget: When to look up vs. decompose vs. search?        |
|                                                                                        |
|  3. THE STOPPING & HALTING PROBLEM                                                     |
|     Determining satisfaction or unsolvability without arbitrary token-count thresholds.|
|                                                                                        |
|  4. CAUSAL DIAGNOSIS & CREDIT ASSIGNMENT                                               |
|     When plan pi fails, which exact step, variable binding, or assumption is at fault? |
|                                                                                        |
|  5. THE COMMUNICATIVE SURFACE REALIZATION TRANSLATION                                  |
|     Generating fluent, context-appropriate natural language without web-scale memorization.|
|                                                                                        |
+----------------------------------------------------------------------------------------+
```

### 7.1 Problem 1: The Goal Parsing and Grounding Gap
* **The Dilemma:** In classical AI, the user inputs PDDL or formal logic. In real-world AI, the user inputs: *"Help, my code crashes when the input array is empty!"*
* **The Challenge:** How can a small, non-massively pretrained model parse natural language into a structured goal tuple $T = (G, s_0, \mathcal{C})$ without hallucinating or requiring an LLM backbone?
* **Plausible Pathway:** Mentor-distilled semantic frame parsing. Instead of understanding the entire universe of language, Paartha trains a compact, structural parser specialized in extracting *Intent, Arguments, Invariants, and Target Modalities* into a standardized Task AST.

### 7.2 Problem 2: Computational Strategy Selection (Algorithm Selection Problem)
* **The Dilemma:** Rice (1976) formulated the Algorithm Selection Problem. When presented with goal $G$, an agent can:
  1. Look up an exact compiled routine in $\mathcal{L}$ (Cost: $O(1)$).
  2. Decompose $G$ into known subgoals via HTN (Cost: $O(b \cdot d)$).
  3. Synthesize a novel DAG via heuristic search / SMT (Cost: exponential in depth).
  4. Query the user for clarification (Cost: human interaction latency).
* **The Challenge:** Selecting the wrong strategy leads to either immediate failure (trying to look up what must be synthesized) or combinatorial timeout (trying to synthesize what already exists).
* **Plausible Pathway:** Explicit meta-cognitive evaluation. A lightweight classifier assessing task novelty, schema compatibility, and constraint complexity against available library signatures.

### 7.3 Problem 3: The Stopping Problem & Verifiability
* **The Dilemma:** In open-ended tasks (e.g., *"Write a thoughtful essay"* or *"Debug this race condition"*), there is no simple binary acceptance predicate like in chess or math.
* **The Challenge:** Without an external unit test, how does the system know when to stop revising? LLMs stop when they generate the `<|endoftext|>` token, driven purely by surface statistics, often truncating arguments prematurely or babbling indefinitely.
* **Plausible Pathway:** Multi-criteria invariant satisficing. Stopping occurs if and only if:
  $$\forall c_i \in \mathcal{C}_{hard}, c_i(s) = \text{TRUE} \quad \wedge \quad \Delta U(s_{t}, s_{t-1}) < \epsilon_{\text{threshold}} \quad \lor \quad \text{ComputeBudgetExhausted}$$

### 7.4 Problem 4: Causal Diagnosis & Credit Assignment
* **The Dilemma:** When an 8-step plan produces an erroneous result, standard neural models propagate loss indiscriminately across all weights, often degrading functional sub-routines (catastrophic interference).
* **The Challenge:** In an isolated primitive architecture, the system must localize the defect: did step 3 pass garbage to step 4, or did step 4 miscompute, or was the input from step 0 corrupted?
* **Plausible Pathway:** Invariant-gated state contracts. Every primitive $P_i$ executes within a typed sandbox that verifies its explicit postconditions $\text{Post}(P_i)$ before committing the state transition to $s_{working}$. The first step that violates an invariant triggers immediate fault localization.

### 7.5 Problem 5: The Surface Realization Grounding
* **The Dilemma:** A compact system may successfully compute the exact symbolic solution to a complex problem, but fail to express it in natural, polite, or professionally formatted text without an LLM.
* **The Challenge:** Separating cognitive reasoning from language fluency without sacrificing user communicability.
* **Plausible Pathway:** Decoupled surface generation. Internal cognition manipulates structured task objects, logic trees, and verified data. A dedicated, constrained language module (e.g., a compact 1B-parameter generative model or template-composition realizer) translates the verified internal state into the user's target language. The generator is strictly an *encoder/decoder*, never the *thinker*.

## 8. Candidate Fundamental Abstractions

We examine four candidate conceptual loops for Paartha's core cognitive engine.

```
Candidate 1: Classical State-Transition Loop
  Goal G ──> [State s] ──> Operator P ──> [State s'] ──> Goal Check Phi(s')

Candidate 2: Scientific Discovery / Hypothesis Loop
  Goal G ──> Generate Hypothesis H ──> Design Experiment E ──> Execute ──> Analyze Delta ──> Update Belief

Candidate 3: Program Synthesis & Repair Loop
  Goal G ──> Synthesize AST ──> Typecheck / Verify ──> Execute on Tests ──> Fault Localize ──> Patch AST

Candidate 4: Hierarchical Goal Reduction (HTN)
  Goal G ──> Decompose to Subgoals {g_1, g_2} ──> Base Primitives P_k ──> Aggregate Results
```

### 8.1 Critical Evaluation of Candidates
* **Candidate 1 (State-Transition):** Too flat. Fails on long-horizon reasoning where intermediate steps are not simple action-state pairs but conceptual sub-problems.
* **Candidate 2 (Hypothesis-Testing):** Ideal for diagnostic tasks (debugging, research), but overly verbose and slow for routine deterministic procedures (calculating statistics, writing standardized boilerplate).
* **Candidate 3 (Program Synthesis & Repair):** Mechanically sound, but strictly limited to domains with formal grammars and deterministic test suites.
* **Candidate 4 (Hierarchical Goal Reduction):** The most cognitively and computationally scalable abstraction, but requires a robust mechanism for decomposing novel goals that have no pre-existing HTN schema.

### 8.2 The Dual-Loop Synthesis: Paartha Cognitive Engine (PCE)
The evidence from cognitive science and automated reasoning indicates that no single flat loop suffices. Cognition is fundamentally bi-level:

```
+========================================================================================+
|                     PAARTHA DUAL-LOOP COGNITIVE ARCHITECTURE (PCE)                     |
+========================================================================================+
|                                                                                        |
|  OUTER LOOP: META-COGNITIVE STRATEGY & GOAL REDUCTION (Deliberate, Slow)              |
|  * Ingests Task T = (G, s_0, C)                                                        |
|  * Consults S_episodic & S_invariants for applicable task schemas                     |
|  * Decomposes complex goals into a Dependency Directed DAG of Subgoals                 |
|  * Selects execution strategy per node: (Direct Primitive | Sub-Plan | Search)         |
|  * Monitors global resource budget B and halts or replans upon systemic failure       |
|                                                                                        |
|         │                                                              ▲               |
|         │ Dispatch Subgoal                                              │ Escalate      |
|         │ with Contract                                                │ Impasse /     |
|         ▼                                                              │ Violation     |
|                                                                                        |
|  INNER LOOP: BOUNDED EXECUTION & INVARIANT AUDITING (Fast, Operational)                |
|  * Binds working state variables in S_working partition                                |
|  * Invokes verified primitive P from Library L                                         |
|  * Checks local postconditions Post(P) and hard constraints C_hard                     |
|  * If PASS: Advance program counter in DAG                                             |
|  * If FAIL: Trigger local repair R_local(P, s, delta) before escalating                |
|                                                                                        |
+========================================================================================+
```

1. **ACA v1.0 Computational Functions:**
   * `SELECT` becomes the strategy selector and operator binding mechanism in the outer loop.

2. **Substrate Alignment (CTX-001 & EXP-019):**

3. **Capability Acquisition (EXP-033):**
   * The capability acquisition pipeline compiles external teacher demonstrations into isolated primitives stored in $\mathcal{L}$. The PCE treats $\mathcal{L}$ as its operational toolbox. If the PCE encounters an impasse where no primitive in $\mathcal{L}$ satisfies a required subgoal, it creates a formal **Capability Gap Record** (the developmental mentor signal).

## 10. Falsifiable Hypotheses

We formulate five crisp, falsifiable hypotheses to guide empirical research into goal-directed reasoning without massive pretraining.

### Hypothesis H-GDR-1: The Independence of Orchestration and Domain Primitives
* **Claim:** An orchestration controller trained purely on abstract task graphs (e.g., DAG scheduling, variable binding, impasse detection) transfers to entirely unseen domain primitives with $>80\%$ of the efficiency of a domain-specialized controller.
* **Falsification Metric:** If an abstract orchestrator evaluated on a novel domain (e.g., symbolic chemistry) requires $>50\%$ retraining of its control weights to successfully sequence verified domain primitives, the hypothesis is **FALSIFIED** (indicating orchestration and domain computation are fundamentally entangled).
* **Status:** `PLAUSIBLE`

### Hypothesis H-GDR-2: Invariant Verification vs. Verbal Self-Reflection
* **Claim:** On multi-step reasoning tasks with intermediate error injections, an independent invariant-checking verifier achieves $>3\times$ higher recovery accuracy than autoregressive verbal self-reflection ("Reflexion").
* **Falsification Metric:** If verbal self-reflection achieves recovery rates within $15\%$ of formal invariant verification across 100 injected failure states, the hypothesis is **FALSIFIED**.
* **Status:** `SUPPORTED` (Strong preliminary backing in literature, e.g., Huang et al., 2023; Valmeekam et al., 2023).

### Hypothesis H-GDR-3: The Representation Bottleneck in Multi-Step Chains
* **Claim:** Maintaining intermediate multi-step reasoning state in natural language tokens incurs an exponential error cascade ($E(k) \propto 1 - (1 - \epsilon)^k$), whereas maintaining intermediate state in typed, invariant-bounded records maintains a linear or sub-linear error rate ($E(k) \le k \cdot \epsilon_{contract}$).
* **Falsification Metric:** If task success rate on a 10-step chain using natural language working state matches or exceeds typed state records, the hypothesis is **FALSIFIED**.
* **Status:** `SUPPORTED` (Directly aligned with Dziri et al., 2023 and EXP-019).

### Hypothesis H-GDR-4: Test-Time Search Efficiency Under Zero Pretraining
* **Claim:** A compact architecture ($<100\text{M}$ parameters) utilizing heuristic tree search over an explicit primitive library $\mathcal{L}$ outperforms a $7\text{B}$-parameter pretrained foundation model evaluated greedily on algorithmic task execution.
* **Falsification Metric:** If the 7B model achieves higher task completion accuracy on algorithmic benchmarks than the 100M model + MCTS search within equivalent inference FLOP budgets, the hypothesis is **FALSIFIED**.
* **Status:** `PLAUSIBLE`

### Hypothesis H-GDR-5: Decoupled Surface Realization Preserves Invariant Fidelity
* **Claim:** Translating a verified symbolic computational result into natural language via a separate surface generator maintains $100\%$ factual fidelity to the internal computation, provided the generator is conditioned on the structured execution trace rather than generating free-form reasoning.
* **Falsification Metric:** If the surface generator introduces factual hallucination or distorts numerical/logical invariants present in the verified execution trace in $>1\%$ of trials, the hypothesis is **FALSIFIED**.
* **Status:** `PLAUSIBLE`

## 11. Proposed Experimental Specifications (Experiments A through F)

To arbitrate these hypotheses, we specify six concrete, minimal experiments designed to run without massive computational infrastructure.

```
+---------------------------------------------------------------------------------------+
|                             GDR EXPERIMENTAL SUITE                                    |
+---------------------------------------------------------------------------------------+
|  [EXP-GDR-A]  Decoupling Reasoning from Language Fluency                             |
|               (Evaluates synthetic task logic under surface permutations)             |
|                                                                                       |
|  [EXP-GDR-B]  Verification Architecture: Formal Invariants vs. Verbal Reflection      |
|               (Tests error detection and recovery under controlled faults)           |
|                                                                                       |
|  [EXP-GDR-C]  Adaptive Strategy Selection Under Strict Compute Budgets                |
|               (Arbitrates between Lookup, Decomposition, and Search)                  |
|                                                                                       |
|  [EXP-GDR-D]  Hierarchical Task Decomposition vs. Flat Autoregression                 |
|               (Measures goal-reduction scaling on multi-step dependencies)            |
|                                                                                       |
|  [EXP-GDR-E]  Causal Credit Assignment and Targeted Plan Repair                       |
|               (Isolates operator vs. plan vs. input failure in broken executions)     |
|                                                                                       |
|  [EXP-GDR-F]  Grounded Goal Parsing from Minimal Natural Language                     |
|               (Tests zero/few-shot translation of natural language into Task DAGs)    |
+---------------------------------------------------------------------------------------+
```

### 11.1 Experiment A: Decoupling Reasoning Performance from Language Fluency
* **Objective:** Determine whether reasoning competence can be accurately evaluated independently of linguistic generation.
* **Protocol:**
  * Create a synthetic algorithmic environment (e.g., Colored Block Relational Algebra or Graph Path Routing).
  * Design 200 tasks requiring 4 to 8 inferential steps.
  * Compare two conditions:
    * *Condition A (Linguistic Chain):* Model outputs full natural language rationale leading to final answer.
    * *Condition B (Structured State Transitions):* Model emits strictly typed state-action transitions `(Op_id, Arg_bindings)` executed on a deterministic VM.
  * Evaluate across 5 surface permutations (varying entity names, syntax style, linguistic framing) while keeping relational graphs identical.
* **Measured Metrics:**
  * Invariant Consistency under Permutation ($ICP = \frac{\text{Consistent Solutions}}{\text{Total Permutations}}$).
  * True Inferential Accuracy ($TIA$, validated by VM state).
* **Falsification Target:** If Condition A exhibits higher invariant stability across surface permutations than Condition B, linguistic representation provides invariant stabilization, falsifying the core premise of decoupled representation.

### 11.2 Experiment B: Verification Architecture — Formal Invariants vs. Verbal Reflection
* **Objective:** Test whether an agent can detect and recover from errors via verbal self-reflection vs. formal invariant checking.
* **Protocol:**
  * Run a multi-step planning task (e.g., multi-table database query construction or multi-step arithmetic routing).
  * In $30\%$ of runs, inject artificial faults at step $k$:
    * Fault 1: Type mismatch in intermediate result.
    * Fault 2: Out-of-bounds numerical output.
    * Fault 3: Logical contradiction against initial constraint.
  * Compare two recovery mechanisms:
    * *Arm 1 (Verbal Reflection / Reflexion):* Present the error string to a language model and ask it to reflect on why it failed and output a revised plan.
    * *Arm 2 (Formal Invariant Auditor):* A deterministic contract verifier checks $\text{Post}(P_k)$. Upon failure, it outputs an exact diagnostic tuple $\delta = (\text{Op}_k, \text{ViolatedConstraint}, \text{ExpectedType}, \text{ActualValue})$ and triggers backtrack to the parent DAG node.
* **Measured Metrics:**
  * Fault Detection Rate ($FDR$).
  * Recovery Success Rate ($RSR = \frac{\text{Runs reaching target } \Phi \text{ post-fault}}{\text{Total faulted runs}}$).
  * Thrashing Count (number of repeated identical errors).
* **Falsification Target:** If Arm 1 achieves $\ge 85\%$ of Arm 2's recovery rate without infinite loops, formal invariant engines are not strictly necessary for simple multi-step recovery.

### 11.3 Experiment C: Adaptive Strategy Selection Under Compute Budgets
* **Objective:** Evaluate whether a compact meta-controller can dynamically select between Direct Lookup, HTN Decomposition, and Combinatorial Search.
* **Protocol:**
  * Construct a benchmark of 300 problems spanning three complexity tiers:
    * Tier 1 (Routine): Solvable by a single library primitive.
    * Tier 2 (Composite): Solvable by a known 2-3 step decomposition schema.
    * Tier 3 (Novel): Requires search/synthesis over 4+ primitives.
  * Enforce strict inference compute budgets ($FLOP_{max} \in \{10^5, 10^7, 10^9\}$ operations).
  * Evaluate a Meta-Controller trained to predict strategy:
    $$\pi_{strategy} \in \{\text{LOOKUP}, \text{DECOMPOSE}, \text{SEARCH}, \text{DELEGATE}\}$$
* **Measured Metrics:**
  * Strategy Selection Accuracy ($SSA$).
  * Budget Efficiency Score ($BES = \frac{\text{Solved Tasks}}{\text{Total Consumed FLOPs}}$).
* **Falsification Target:** If a naive static strategy (always search or always decompose) matches or exceeds the Meta-Controller's efficiency under varying budgets, dynamic strategy selection adds unnecessary complexity.

### 11.4 Experiment D: Bounded-Horizon Goal Reduction vs. Flat Autoregression
* **Objective:** Compare error accumulation in hierarchical goal reduction vs. flat autoregressive generation as plan depth $d$ increases.
* **Protocol:**
  * Evaluate plan generation on tasks with dependency depths $d \in \{2, 4, 6, 8, 10, 12\}$.
  * *Architecture 1 (Flat Autoregressive):* Generates entire action sequence end-to-end $\langle a_1, a_2, \dots, a_d \rangle$.
  * *Architecture 2 (Hierarchical Goal Reduction):* Recursively reduces goal $G \to \{g_1, g_2\}$ until subgoals match verified primitive contracts, executing subgoals immediately to ground intermediate state before expanding downstream branches.
* **Measured Metrics:**
  * Success rate vs. depth $d$.
  * Premature goal abandonment rate.
* **Falsification Target:** If Architecture 1's success rate decays at the same or lower rate than Architecture 2 as $d \to 12$, hierarchical goal reduction provides no architectural protection against depth-induced error compounding.

### 11.5 Experiment E: Causal Credit Assignment and Targeted Plan Repair
* **Objective:** Test whether a failed execution can be repaired locally without invalidating successfully executed sub-plans.
* **Protocol:**
  * Given a verified 6-step DAG where step 4 fails due to an environmental edge case.
  * *Baseline:* Regenerate the entire plan from scratch given the error message.
  * *PCE Repair:* Freeze steps 1-3 ($s_3$ preserved in $S_{working}$), replace sub-DAG spanning steps 4-5 with an alternative candidate primitive, and resume execution from $s_3$.
* **Measured Metrics:**
  * Repair Latency (FLOPs to recover).
  * Preservation of Prior Valid Work ($PPW = \frac{\text{Unmodified correct steps}}{\text{Total prior steps}}$).
* **Falsification Target:** If whole-plan regeneration achieves identical success with lower compute overhead than local DAG splicing, isolated state preservation is not justified for short-horizon tasks.

### 11.6 Experiment F: Grounded Goal Ingestion from Minimal Natural Language
* **Objective:** Measure the minimum parameter count and dataset scale required to reliably parse natural language task requests into formal Task ASTs.
* **Protocol:**
  * Curate 1,000 diverse natural-language goal prompts across 5 task domains (math, file transformation, data extraction, scheduling, logic puzzles).
  * Train compact sequence-to-tree parsers of varying parameter sizes: $10\text{M}, 35\text{M}, 100\text{M}, 500\text{M}$.
  * The target representation is an explicit Task AST:
    ```json
    {
      "intent": "FIND_MINIMAL_PATH",
      "target_predicate": "path.is_valid() && path.weight == min(all_paths)",
      "inputs": {"graph": "$var_0", "source": "A", "dest": "B"},
      "invariants": ["no_negative_cycles", "max_latency_ms < 500"]
    }
    ```
* **Measured Metrics:**
  * Syntactic Validity Rate ($SVR$).
  * Semantic Invariant Match Rate ($SIMR$).
* **Falsification Target:** If models with $<500\text{M}$ parameters fail to achieve $>90\%$ $SIMR$ even on in-distribution phrasing, semantic goal ingestion is an intractable bottleneck for small models, forcing reliance on larger external foundation parsers.

## 12. Evaluation Methodology: Separating Reasoning from Fluency

A fatal flaw in modern AI evaluation (e.g., GSM8K, HumanEval, MMLU) is that benchmark scores conflate linguistic fluency, world-knowledge memorization, and actual reasoning competence. To ensure scientific rigor, Paartha adopts a four-part evaluation methodology:

```
+-----------------------------------------------------------------------------------+
|                   PAARTHA DECOUPLED EVALUATION METHODOLOGY                        |
+-----------------------------------------------------------------------------------+
|                                                                                   |
|  1. GOAL ACHIEVEMENT RATE (GAR)                                                   |
|     Binary evaluation of target predicate: Did state s* satisfy Phi(s*)?          |
|     Evaluated by external VM / compiler / environment, NOT an LLM judge.          |
|                                                                                   |
|  2. INVARIANT VIOLATION RATE (IVR)                                                |
|     Count of hard safety, type, or logical constraint violations during execution: |
|     IVR = (Violations across all steps) / (Total steps)                           |
|                                                                                   |
|  3. RECOVERY EFFICIENCY (RE)                                                      |
|     Ability to reach Phi(s*) when intermediate faults are injected:               |
|     RE = (Success Rate under Faults) / (Success Rate on Clean Runs)               |
|                                                                                   |
|  4. COMPUTATIONAL BUDGET EFFICIENCY (CBE)                                         |
|     Task completion relative to energy and inference FLOPs:                       |
|     CBE = GAR / (log10(FLOPs) * Latency_seconds)                                  |
|                                                                                   |
+-----------------------------------------------------------------------------------+
```

### 12.1 The Permutation Invariance Test
To verify that the system is genuinely computing rather than surface-matching:
* Any evaluation task must be executable across $N$ semantically isomorphic permutations:
  * Variable name substitution ($x \to \text{foo}$, $\text{city} \to \text{node}_{42}$).
  * Syntactic transposition (prefix vs. postfix, imperative vs. functional).
  * Distractor insertion (irrelevant narrative details added to the prompt).
* **True Reasoning Score ($TRS$):** A task is scored as SUCCESS if and only if it passes all $N$ permutations. A model that solves $80\%$ of individual runs but drops to $10\%$ on permutation consistency is memorizing surface patterns, not reasoning.

## 14. What Remains Unknown

The following critical questions are currently unresolved and cannot be settled by theory alone:
1. **The Ingestion Boundary:** What is the minimal linguistic interface required for a non-pretrained agent to understand a human request? Does Paartha ultimately require an external SLM (Small Language Model, 1B-3B) as an ingestion frontend, or can a structured grammar/semantic parser suffice for a defined operational domain?
2. **Dynamic Impasse Resolution:** When the PCE encounters a problem where no composition of library primitives can achieve goal predicate $\Phi$, how does it formalize what capability is missing? Can it automatically synthesize a pedagogical prompt to ask a human or mentor model for the specific missing primitive?
3. **Continuous-Discrete Interface:** How does continuous neural state (e.g., an invariant feature embedding) bind into discrete symbolic execution arguments without precision loss or out-of-distribution discretization collapse?
4. **Generalization of Verification:** Formal verification is trivial for unit tests, math, and code syntax. How does Paartha verify "soft" goals (e.g., *"Write a polite and persuasive email"* or *"Summarize this research neutrally"*) without re-introducing subjective, ungrounded LLM judges?

## 15. What Should NOT Yet Be Implemented

To prevent wasted engineering and premature commitment to unvalidated abstractions, we establish strict negative boundaries:

1. **Do NOT build a generic "LLM Agent" loop:**
   * Implementing an AutoGPT/CrewAI-style loop (prompting a foundation model with `Thought: / Action: / Observation:`) solves none of Paartha's core problems, inherits all LLM pathologies, and violates the foundational premise of pretraining-free cognition.
2. **Do NOT invent a complex custom Domain-Specific Language (DSL):**
   * Do not design an idiosyncratic programming language or execution VM for Paartha plans before Experiment F and Experiment A demonstrate that existing representations (e.g., standard Python ASTs, computation DAGs, or PDDL subsets) are fundamentally inadequate.
3. **Do NOT hard-code a massive, brittle ontology of world rules:**
   * Hand-coding thousands of manual STRIPS rules or Cyc-style ontological assertions creates an unmaintainable, brittle system that fails to generalize. Capabilities must be acquired through mentor distillation (EXP-033), not manual hard-coding.
4. **Do NOT train an end-to-end monolithic transformer to "reason":**
   * Training a small transformer on reasoning chains will merely produce an inferior, low-capacity imitation of frontier LLMs, exhibiting identical hallucinations and catastrophic forgetting.
