## 1. Candidate Abstraction Definition: Closed-Loop Discrepancy Reduction (CDR)

Following the adversarial audit in `GDR-002`, which falsified the 7-faculty cognitive taxonomy and the static Paartha Cognitive Engine (PCE) dual-loop as premature architectures, `GDR-002` offered a candidate common abstraction: **Closed-Loop Discrepancy Reduction (CDR)**.

Mathematically, CDR posits that goal-directed problem solving is an iterative feedback control loop:
$$s_{t+1} = \tau(s_t, a_t)$$
$$\Delta(s_t, G) = \mathcal{D}(s_t, G)$$
$$a_t \sim \pi(a \mid s_t, G, \Delta)$$
$$\text{Stop if } \Delta(s_t, G) \le \epsilon \quad \lor \quad \text{ComputeBudgetExhausted}$$

Upon unexpected state transition or invariant violation:
$$\text{If } s_{t+1} = \text{FAULT}, \quad \text{Rollback to checkpoint } s_{chk}, \quad \text{Prune } a_t, \quad a_t' \sim \pi(a \mid s_{chk}, G, \Delta \setminus \{a_t\})$$

The core hypothesis under test in this document is:
> **Can goal-directed problem solving across substantially different task types be represented as closed-loop state transformation driven by measurable discrepancy reduction?**

---

## 2. Origin of the Hypothesis

The CDR hypothesis arose to resolve a specific failure mode in `GDR-001`. In `GDR-001`, the system required an upfront static DAG planner, a separate causal repair engine, a 7-faculty modular pipeline, and a universal Task AST. 

`GDR-002` audited these constructs and showed:
1. Upfront DAG planning fails on reactive, stochastic, or interactive tasks.
2. Causal root-cause repair is $NP$-hard and less effective than state-rollback search.
3. The 7 faculties are an intuitive descriptive convenience reducible to standard cybernetic control.

CDR was proposed as the simplest mechanism capable of combining **dynamic execution feedback** with **goal-directed search**, without hard-coding a static executive.

---

## 3. Why CDR Might Be More Fundamental Than PCE

CDR possesses three theoretical virtues over PCE:
1. **Parsimony:** Instead of seven distinct modules (Knowing, Computing, Selecting, Executing, Verifying, Recovering, Communicating) and two asynchronous loops, CDR operates on a single state-action-feedback loop.
2. **Unified Recovery:** Recovery is not a separate engine; it is simply the next iteration of search from a rolled-back state checkpoint $s_{chk}$ after an assertion fails.
3. **Reactive Flexibility:** Because actions are evaluated step-by-step against current state rather than compiled into an upfront rigid DAG, the system natively handles non-deterministic environment transitions.

---

## 4. Counterarguments: The Strongest Attacks Against CDR

Despite its elegance, CDR faces five severe foundational objections:

1. **The Tautological Semantic Blanket (Unfalsifiability Risk):** If "discrepancy" is defined so broadly that any internal mental state, surprise, curiosity, or unfinished sentence is labeled a "discrepancy", CDR becomes a useless tautology. Any Turing machine transition from tape state $q_i$ to $q_j$ can be post-hoc described as "reducing discrepancy to halting state $q_{halt}$". To remain scientific, discrepancy must be **computable, measurable, and falsifiable**.
2. **The Non-Convex Metric Trap (Deceptive Manifolds):** In complex reasoning, discrepancy is almost never monotonic or convex. A state that appears superficially closer to the goal (e.g., dropping all unsorted records to achieve 0 inversions) can permanently destroy necessary prerequisites.
3. **Epistemic Blindness:** When an agent must gather information (e.g., reading a schema, profiling a slow query, asking a user for clarification), physical distance to the goal does not decrease ($\Delta(s', G) = \Delta(s, G)$). A pure discrepancy-reducing policy will never take an epistemic action.
4. **Subjective & Unbounded Domains:** In open-ended writing, strategic design, or creative synthesis, there is no closed-form target state $s^*$. Who computes $\Delta$? If $\Delta$ requires an omniscient critic, CDR simply sweeps the entire difficulty of intelligence into an uncomputable evaluation oracle.
5. **The Representation Transformation Discontinuity:** In real problem solving, the system transforms representations across distinct formal systems:
   $$\text{Natural Language} \longrightarrow \text{Task Specification} \longrightarrow \text{Algorithm} \longrightarrow \text{Executable AST} \longrightarrow \text{State Trace}$$
   These are not incremental numerical movements toward a target vector; they are **discrete categorical compilations**.

To avoid committing to CDR prematurely, we examine five competing candidate abstractions:

```
Candidate A: Closed-Loop Discrepancy Reduction (CDR)

Candidate B: Goal-Directed Representation Transformation (GDRT)
  Representation R_0 (NL) ──Compile──> R_1 (Spec) ──Synthesize──> R_2 (AST) ──Execute──> R_3 (State)

Candidate C: Heuristic Search Over Computational Trajectories (HSCT)
  Search Graph: Nodes = States, Edges = Library Operators P in L. A* / MCTS over trajectory space.

Candidate D: Active Inference & Epistemic Free Energy Minimization (AIF)
  Action a_t minimizes Variational Free Energy: Pragmatic Value (Goal match) + Epistemic Value (Info gain).

Candidate E: Program Synthesis & Inductive Repair (PSIR)
  Specification ──Sample Candidate──> Program P ──Execute on Tests──> Counterexample ──Patch AST
```

## 6. Literature Comparison: The Novelty Test

Does CDR add anything novel beyond existing frameworks?

* **Cybernetics (Wiener, 1948):** Formulated negative feedback loops minimizing error $e(t) = y_{target} - y(t)$. CDR is mathematically identical.
* **TOTE Unit (Miller, Galanter, Pribram, 1960):** *Test-Operate-Test-Exit*. CDR is the exact TOTE unit applied to computational primitives.
* **Means-Ends Analysis (Newell & Simon, 1959 - General Problem Solver):** Explicitly identified differences between current state and goal state, searching for operators that reduce those differences.
* **Model Predictive Control (MPC / Receding Horizon):** Plans $H$ steps into the future, executes the first step, observes state, and replans.

**Verdict on Novelty:** CDR is **NOT** a new discovery by Paartha. It is a re-labeling of **Means-Ends Analysis (1959)** and **Cybernetic Feedback Control (1948)**. Claiming novelty for the loop itself is scientifically invalid. Paartha's sole research focus must be: **What is the empirical behavior of search and feedback over isolated modular capability libraries?**

## 7. Mathematical Formalization of Problem Domains

To evaluate where CDR holds and where it breaks, we formally distinguish the components of a task:

1. **State Space ($\mathcal{S}$):**
   $$s_t = \langle s^{int}_t, s^{ext}_t, s^{hist}_t \rangle$$
   * $s^{int}_t$: Internal working memory, active hypotheses, variable bindings in $S_{working}$.
   * $s^{ext}_t$: Observable environment (data, files, terminal, database).
   * $s^{hist}_t$: Execution history and tried operator stack.
2. **Action Space ($\mathcal{A}$ or $\mathcal{L}$):**
   * **Pragmatic Actions ($a_{prag}$):** Operators that mutate $s^{ext}_t$ toward goal satisfaction.
   * **Epistemic Actions ($a_{epis}$):** Operators that mutate $s^{int}_t$ by acquiring information (probing schemas, inspecting types), where $\Delta(s^{ext}, G)$ is unchanged but internal Shannon entropy $\mathcal{H}(s^{int})$ decreases.
3. **Discrepancy Function ($\mathcal{D}$):**
   $$\mathcal{D}: \mathcal{S} \times \mathcal{G} \to \mathbb{R}^+ \cup \{\infty\}$$
   * Metric property: $\mathcal{D}(s, G) = 0 \iff s \models \Phi(G)$.
   * Admissibility: $\mathcal{D}(s, G) \le h^*(s, G)$ (true cost-to-go).

## 9. Empirical Benchmark Specification: EXP-CCS-0

To empirically test the limits of CDR, greedy discrepancy minimization, open-loop planning, and heuristic search, we implemented and executed **`EXP-CCS-0`** (`experiments/exp_ccs0_capability_composition_search/run.py`).

### 9.1 The Six Experimental Task Families
1. **Family 1 (Deterministic Chaining):** Multi-step sequential composition ($A \to B \to C$) requiring deduplication, filtering, and ascending sorting.
2. **Family 2 (Compositional Generalization):** An unobserved 4-step sequence (`Scale -> FilterMin -> SortDesc -> Dedupe`) combining independently acquired primitives.
3. **Family 3 (Fault Injection):** Execution fault injected into primary sorting operator ($70\%$ crash rate). Measures recovery and fallback path discovery.
4. **Family 4 (Hidden Structure / Dead Ends):** Contains a deceptive `GreedyTrapShortcut` primitive that sets values to 999 (mimicking target row count and sorting) but destroys data integrity invariants.
5. **Family 5 (Partial Observability / Epistemic Action):** Encoded records requiring an `EPISTEMIC_PROBE_METADATA` operator before `DECRYPT_ENCODED` can be legally applied.
6. **Family 6 (Ambiguous Objective):** Multiple disjoint paths satisfy the goal predicate (either Category A or Category B, length 2, sorted).

### 9.2 The Five Competitor Baselines
* **B1 (StaticPlan):** Upfront open-loop plan formation via greedy simulation at start; executes without intermediate observation or recovery.
* **B2 (Greedy):** Step-by-step myopic discrepancy reduction: $a^* = \arg\min_a \mathcal{D}(s', G)$. Halts upon local plateau.
* **B3 (TreeSearch):** Best-first A* lookahead search over the state-action space using discrepancy as heuristic cost-to-go.
* **B4 (CDR with Rollback):** Closed-loop step-by-step execution with active assertion monitoring, state checkpointing, and depth-bounded backtracking rollback.
* **B5 (LearnedPolicy):** Nearest-neighbor supervised policy mapping state feature signatures directly to candidate operators (simulating demonstration training).

## 11. Empirical Analysis & Discovery of Core Pathologies

The experimental data from `EXP-CCS-0` establishes five decisive empirical findings:

### Finding 1: The Greedy Discrepancy Trap (Failure of Myopic CDR)
In T1 and T2, `Greedy` achieved **0.00% success**. Detailed trace analysis revealed why:
* After applying `FILTER_CAT_A`, the state had 4 records: `[id:1, id:1, id:3, id:5]` with values `[12, 12, 25, 8]`.
* The required target was length 3, sorted, unique IDs: `[id:5, id:1, id:3]` (`[8, 12, 25]`).
* The primitive `FILTER_VAL_MIN_10` dropped `id:5` (val 8), leaving 3 records with values `[12, 12, 25]`.
* Because length was now exactly 3 and values were sorted, **discrepancy dropped to 1.0 (apparent near-perfection)**.
* However, `id:5` was irreversibly lost, and the duplicate `id:1` remained. Greedy was trapped in a local minimum and halted.
* **Conclusion:** Closed-loop myopic discrepancy reduction without tree search is fundamentally brittle against deceptive subgoals.

### Finding 2: Tree Search Dominates Open-Loop and Greedy Execution
Across both Exp 1 and Exp 2, `TreeSearch` was the **only mechanism that solved T1, T2, T4, T5, and T6 consistently**. By maintaining a priority frontier over multiple trajectory branches, tree search bypassed the deceptive shortcuts that seduced greedy descent.

### Finding 3: The State Rollback Advantage Under Runtime Faults
In T3, where the primary sorting operator crashed with $70\%$ probability:
* `StaticPlan` and `TreeSearch` executed open-loop plans: when `FAULTY_SORT` was selected and crashed, execution aborted immediately (achieving only $80\%$ success on seeds where the primary didn't crash or alternative was picked).
* `CDR_Rollback` achieved **100% success** with a **0.20 recovery rate**. Upon runtime crash, it rolled back state to the checkpoint, pruned the crashed primitive, selected `SortByValue(ascending=True)`, and completed the task.
* **Conclusion:** Checkpoint rollback is an effective and necessary mechanism for runtime fault recovery.

### Finding 4: Epistemic Blindness Is Empirically Real
In Exp 1 (T5), where data was encoded, all baselines using naive discrepancy failed (0.00% success). Because `EPISTEMIC_PROBE_METADATA` modified internal working memory rather than raw data, physical discrepancy did not decrease. Only when discrepancy was explicitly calibrated to reward information gain did the system discover the probe.

### Finding 5: Exponential Combinatorial Explosion in Pure Search
Exp 3 demonstrated that transitions in `TreeSearch` grew from 15 at Depth 2 to 160 at Depth 4. Unconstrained search over large primitive libraries faces combinatorial collapse unless guided by learned heuristics or macro-primitives.

## 12. Deeper Abstraction Synthesis: What Actually Computes?

Comparing the hypotheses:
* **Hypothesis A (Intelligence is Closed-Loop Discrepancy Reduction):** **FALSIFIED in its strong form.** Discrepancy functions are non-convex, vulnerable to reward hacking, blind to epistemic actions, and uncomputable in open-ended domains.
* **Hypothesis B (Intelligence is Goal-Directed Representation Transformation):** **SUPPORTED.** Cognition compiles ambiguous natural language into structured constraints, maps constraints to executable operators, and translates outputs back to interface representations.
* **Hypothesis C (Intelligence is Search over Computational Trajectories):** **ESTABLISHED.** In all empirical tasks, problem solving succeeded if and only if systematic search (BFS / A* / Lookahead with Rollback) was performed over candidate compositions.

### The Unified Synthesis: Search Over Executable Transformations with Checkpoint Rollback (SET-CR)

Intelligence in a capability-based architecture is not a magical scalar discrepancy reducer. It is:
$$\text{Task Goal } G \longrightarrow \text{Search Engine} \left[ \text{Evaluate Candidates in } \mathcal{L} \xrightarrow{\text{Execute on State Snapshot}} \text{Assertion Invariant Check} \right] \xrightarrow{\text{On Failure}} \text{Rollback \& Branch}$$

## 13. What Does Paartha Actually Do Internally When "Thinking"?

When a user presents Paartha with an unfamiliar problem ("debug this deadlock", "synthesize this algorithm"), Paartha does **not** emit a stream of autoregressive tokens and call it reasoning.

Internally, Paartha executes four concrete computational phases:
1. **Frame Ingestion:** Maps external input into a working state hypothesis $s_0$ and acceptance constraints $\Phi$.
2. **Trajectory Search:** Explores candidate compositions of verified primitives from $\mathcal{L}$ against snapshots of $S_{working}$.
3. **Execution & Checkpointing:** Advances state through selected operators, taking snapshots at critical contract boundaries.
4. **Invariant Auditing & Rollback:** Evaluates assertions against intermediate state. If an invariant fails, it rolls back state to the snapshot and branches on an alternative operator.

Thinking is **adaptive computation over internal state snapshots mediated by capability search and invariant verification**.

## 14. What Survives, What Is Downgraded, and What Is Rejected

### What Survives (Established Truths)
1. **Inference-Time Search is Irreducible:** Neither greedy execution nor static open-loop planning can solve composite multi-step tasks with deceptive subgoals. Systematic search over capability compositions is mandatory.
2. **State Checkpointing and Rollback are Essential for Fault Recovery:** When runtime faults occur, rolling back to a clean state snapshot and branching is computationally superior to fragile causal diagnosis or total task abort.
3. **The Competence-Orchestration Separation:** Having primitives in $\mathcal{L}$ is distinct from orchestrating them; orchestration requires search over operator sequences.

### What Is Downgraded to Open Hypothesis
* **Epistemic Entropy Integration:** Whether internal information gain can be universally unified with task progress into a single objective (e.g., Active Inference Free Energy) without hand-crafted domain bonuses.
* **Macro-Primitive Discovery:** Whether frequent successful search trajectories can be compiled into new atomic primitives in $\mathcal{L}$ to prevent combinatorial explosion as sequence depth grows.

### What Is Formally Rejected
1. **REJECTED: Pure Closed-Loop Discrepancy Reduction (CDR):** Discarded as an autonomous general architecture. Fails under deceptive local minima, unaligned heuristics, and epistemic actions.
2. **REJECTED: Myopic Greedy Step Selection:** Discarded. Fails on basic multi-step composition tasks ($0.00\%$ success on T1/T2).
3. **REJECTED: Static Open-Loop Plan Generation:** Discarded. Fails whenever runtime faults or stochastic transitions occur.
4. **REJECTED: CDR Novelty Claim:** Retracted. Identified as historical Means-Ends Analysis (Newell & Simon, 1959) and Cybernetic Feedback Control (Wiener, 1948).

In subjective, open-ended domains (emails, creative design), search requires **human-in-the-loop interactive critique** or a pretrained linguistic interface, NOT an imaginary autonomous verifier.
