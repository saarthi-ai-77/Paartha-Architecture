## 1. Research Objective & The Progressive Capability Ladder

- **Weights** are a monolithic tensor bundle capturing fuzzy statistical correlations.
- **Context** is an unstructured sequence of token embeddings in an attention window.
- **Inference** is myopic autoregressive next-token sampling: $P(w_t \mid w_{<t})$.

## 4. Existing Memory and State Substrates in the Architecture

Paartha's architecture does not treat state as an undifferentiated latent vector. It formalizes state into three primary structural substrates plus a rigorously tested partition discipline:

### 4.1 $S_{episodic}$ (Episodic Memory / Experience Store)
- **Status**: `IMPLEMENTED` & `EXPERIMENTALLY VALIDATED` (EXP-001, EXP-019, EXP-022; bounded scope per EXP-018).
- **Physical Structure**: Fixed-capacity, content-addressable key-value store (`EpisodicMemory` in `runtime/sip001/memory.py`).
- **Co-resident Schemas**:
  1. `fact`: `name_id -> city_id`. Input-representation to verified output mapping.
  2. `routing`: `input_signature -> family_id`. Learned dispatch decisions (namespaced per IVS-001).
  3. `self_model`: `skill_id -> probe_score`. Evaluated competence boundaries.
  4. `unknown`: `flagged_input -> context`. Low-confidence triggers queued for curriculum review.
  5. `episode`: `episode_id -> execution_trace`. Structured record of past interaction cycles.
- **Write Disciplines**:
  - *Competence-Gated Write*: Writes entry only when local prediction entropy exceeds running median ($H(x) > \text{median}(H)$); evicts lowest-entropy entry when full. Validated under static distributions (EXP-001), but susceptible to **Write Starvation** when saturated (EXP-019) and single-exposure lockout (EXP-022).
  - *Unconditional Write*: Bypasses entropy thresholding; writes directly to key. Required for single-exposure teaching (EXP-022) and reserved working state (EXP-019).

### 4.2 $S_{semantic}$ (Slow Parameter Backbone)
- **Status**: `IMPLEMENTED` & `EXPERIMENTALLY VALIDATED` (EXP-001, EXP-018, EXP-021).
- **Physical Structure**: Trainable neural network parameters (e.g., `CausalTransformerLM` in `runtime/sip001/recall_model.py`, 4 layers, $d_{\text{model}}=128$, 619k parameters).
- **Update Cadence**: Continuous stochastic gradient descent (`torch.optim.Adam`) over slow timescales.
- **Empirical Boundary**: Subject to catastrophic forgetting under sequential, non-rehearsed distributions (`EXP-018`: 0% recall on early stages). One-time replay consolidation was **FALSIFIED** by EXP-010 (0.160 vs 0.158 baseline). 

### 4.3 $S_{invariants}$ (Structural & Domain Invariants)
- **Status**: `IMPLEMENTED` & `EXPERIMENTALLY VALIDATED` (EXP-020, EXP-026, KRS-001).
- **Physical Structure**: Read-only, externally supplied or formally verified logical rules, grammars, and algebraic symmetries (`InvariantRule` in `runtime/aca0/krs.py`; SCAN grammar in `runtime/sip001/compose.py`).
- **Writing Authority**: **None at runtime**. No internal learning module is permitted to alter or overwrite $S_{invariants}$.
- **Access Function**: Evaluated by `EVALUATE-STRUCTURAL` and deductive reasoning engines. Guarantees 100% exact compositional generalization without out-of-distribution drift.

### 4.4 The Status of $S_{working}$ (Working State / Context Partition)
- **Status**: **FALSIFIED as a separate substrate (EXP-019); VALIDATED as a reserved-capacity partition within $S_{episodic}$**.
- **Historical Analysis**: In `docs/12_cognition/CTX-001.md`, a separate 4th substrate ($S_{working}$) was hypothesized based on an access-pattern mismatch: conversation context requires in-place field updates rather than content-addressable key eviction.
- **Empirical Falsification (EXP-019)**:
  - Condition A (Naive shared $S_{episodic}$ with schema tags): **Collapsed to $0.200 \pm 0.100$ recall** due to *Write Starvation*.
  - Condition B (Separate dedicated buffer): Achieved **$1.000 \pm 0.000$ recall**.
  - Condition C (Reserved partition within $S_{episodic}$ + unconditional write): Achieved **$1.000 \pm 0.000$ recall**.
- **Conclusion**: Structural separation is unneeded. A reserved slot partition written unconditionally achieves perfect recall without multiplying substrates. Implemented as `WorkingStateStore` in `runtime/sip001/context_state.py`.

## 7. Existing Inference Mechanisms in Paartha

Mainstream inference is autoregressive token prediction. In Paartha, inference has been implemented and validated through three distinct computational mechanisms:

```
+---------------------------------------------------------------------------------------------------+
|                                 PAARTHA INFERENCE ARCHITECTURES                                   |
|                                                                                                   |
| 1. Dual-Pathway Pipeline (SIP-001):                                                               |
|    Request -> Fixed Router -> [Recall Pathway: CausalTransformerLM + S_episodic Gated Read]       |
|                            -> [Compose Pathway: SCAN AST Parser + Linear Lookup (EXP-020)]        |
|                                                                                                   |
| 2. Symbolic Invariant Deduction (ACA-0 / KRS-001):                                                |
|    Query -> Entity/Relation Match -> Invariant Rule Engine -> Proof Trace -> Verbal Explanation   |
|                                                           \-> Counterfactual Mutation ($S'_{count})|
|                                                           \-> Clarification Trigger               |
|                                                                                                   |
| 3. Search Over Executable Transformations (SET-CR / GDR-003):                                     |
|    Goal -> State Evaluation -> Candidate Primitive Expansion -> Checkpoint -> Rollback / Branch  |
+---------------------------------------------------------------------------------------------------+
```

1. **Dual-Pathway Request Handling (`runtime/sip001/runtime.py`)**:
   - Ingress request is typed (`kind`).
   - If factual: passes through `CausalTransformerLM` forward pass. If output entropy is high ($H > 1.5\text{ nats}$), queries `EpisodicMemory`. If found, overrides prediction; if missing, returns `"I do not know"` and logs an unknown.
   - If grammatical/compositional: passes through `StructureMatchedCompose`, executing AST reduction with 100% exact match.
2. **Deterministic Deductive & Counterfactual Inference (`runtime/aca0/reasoning.py`)**:
   - Matches relations in $\mathcal{E}_R$.
   - Applies forward/backward chaining over invariant implication rules in $\mathcal{C}_I$.
   - Generates exact causal proof traces ($\text{Subject} \xrightarrow{\text{is\_a}} \text{Category} \xrightarrow{\text{Rule}} \text{Predicate}$).
   - Simulates hypothetical counterfactual worlds by copying the graph ($S'_{counter} = \mathcal{K}.\text{copy}()$), severing old edges, adding mutated premises, and auditing whether conclusions survive.
3. **Search Over Executable Transformations with Checkpoint Rollback (SET-CR, `GDR-003`)**:
   - Given initial state $s_0$ and goal predicate $G(s)$, searches through executable transformation primitives $T \in \mathcal{L}$.
   - Evaluates progress via heuristic distance $f(n) = g(n) + h(n)$.
   - Creates execution checkpoints; when an action encounters an invariant failure or local deception, rolls back state cleanly to the checkpoint and branches into alternative search paths.

## 8. Relationship to Capability Acquisition (EXP-033)

In `docs/05_research/`, the central research hypothesis of Paartha was framed as:

> **Can an AI system turn acquired experience or externally taught capability into independently reusable computational structure — then retain, verify, and compose that structure without retraining the whole system?**

The archaeological recovery clarifies how this connects directly to state substrates:
1. **The Fallacy of Monolithic Ingestion**: Mainstream LLMs attempt to force all capability acquisition into parameter updates of a single dense matrix ($\Delta W$). This causes catastrophic interference (EXP-018) and unpredictable regression.
2. **State Partitioning for Acquisition**:
   - New declarative facts enter $S_{episodic}$ via unconditional first-exposure writes (EXP-022) or relational edges $\mathcal{E}_R$ (KRS-001).
   - New behavioral capabilities or procedural tools enter the **Capability Library** ($\mathcal{L}$) as isolated executable primitives (functions, AST transformations, neural adapters).
   - Invariants and boundary constraints enter $S_{invariants}$ ($\mathcal{C}_I$), acting as non-negotiable verification gates.
3. **Zero-Retraining Reuse**: When a new capability primitive is acquired in $\mathcal{L}$, the core backbone parameters are untouched. The system composes the new primitive at runtime via SET-CR search or explicit routing without risking prior competence.

## 9. Relationship to SET-CR and Goal-Directed Reasoning (GDR-003)

`GDR-001` proposed a 7-faculty cognitive architecture with a static DAG planner. `GDR-002` dismantled this as premature, reducing goal-directed behavior to Closed-Loop Discrepancy Reduction (CDR). `GDR-003` and `EXP-CCS-0` then subjected CDR to empirical testing, discovering that pure myopic discrepancy reduction collapses ($0.0\%$ success) in the presence of deceptive subgoals and epistemic blindness.

The verified solution — **SET-CR (Search over Executable Transformations with Checkpoint Rollback)** — directly defines how inference operates over state:
- **Search Space**: Transitions between discrete states $s \in \mathcal{S}$ generated by applying capability primitives from $\mathcal{L}$.
- **Working Partition**: Each search node maintains an ephemeral state delta within the working partition.
- **Rollback Discipline**: Because transformations are applied in an isolated sandbox, failed execution branches simply discard the local state delta and revert to the parent checkpoint without corrupting persistent memory ($S_{episodic}$) or knowledge graphs ($\mathcal{K}$).

## 11. The Three Kinds of State

From ARS-001, SOS-001, CTX-001, and PCS-001, Paartha's state model decomposes cleanly into three distinct categories based on lifespan, mutability, and access topology:

```
                                  PAARTHA THREE-TIER STATE MODEL

  [A] PERSISTENT LEARNED STATE (Weights & Rules)
      - Slow Parameter Backbone (S_semantic: CausalTransformerLM, ~619k params)

      - Formal Invariant Constraints (S_invariants / C_I: Static, read-only logical rules)

  [C] TRANSIENT COMPUTATIONAL STATE (Working & Search State)
      - Reserved Working Partition (WorkingStateStore: topic, speaker, goal, active slots)
      - Reasoning Chain State (RC-03: Intermediate execution step values)
      - SET-CR Search Tree (Frontier nodes, heuristic scores f(n), checkpoint rollbacks)
```

## 12. What Plays the Role of "Weights"?

In Paartha, "weights" are not an undifferentiated 100-billion-parameter array that encodes grammar, facts, reasoning, tools, and world history simultaneously. 

Instead, persistent learned competence is divided into three distinct mechanisms:
1. **Compact Neural Encoders/Decoders ($S_{semantic}$)**:
   - Small, parameter-efficient neural modules (e.g., $10^5$ to $10^7$ parameters, rather than $10^{11}$).
   - Purpose: Continuous perceptual processing, token embedding, phonetic/textual representation, and fuzzy similarity matching.
2. **Isolated Modular Primitives in the Capability Library ($\mathcal{L}$)**:
   - Discrete, specialized parameter containers (e.g., the 326-parameter primitive classifier from EXP-020, symmetry group actions from EXP-002, or specific AST transformations).
   - Purpose: Executing specialized transformations without cross-talk or catastrophic interference.
3. **Formal Structural Invariants ($S_{invariants}$)**:
   - Non-trainable, zero-parameter symbolic rules, grammars, and algebraic symmetries.
   - Purpose: Enforcing absolute guarantees on syntax, logic, and physical/domain laws.

---

## 13. What Plays the Role of "Context"?

In standard LLMs, "context" is an unbounded, contiguous sequence of raw tokens concatenated in a buffer and scanned by quadratic attention.

In Paartha, context is **factored, bounded, and structured**:
1. **The Active Working State (`WorkingStateStore`)**:
   - A small, fixed set of typed fields (e.g., `current_topic`, `active_goal`, `speaker_intent`, `entity_focus`).
   - Updated **unconditionally** on every turn (EXP-019). It does not grow indefinitely with conversation length; it is updated in place.
2. **The Structured Episode Trace ($s^{hist}$)**:
   - A sequential log of previous interaction turns, actions, confidence scores, and outcomes stored on disk (`episodes.jsonl`).
   - Referenced when an explicit conversational backward-lookup is required ("What did I ask you two turns ago?").
3. **Dynamic Context-Addressable Retrieval**:
   - When a specific entity or topic is referenced in the working state, relevant relational facts ($\mathcal{E}_R$) and episodic records ($S_{episodic}$) are retrieved on demand and bound to the active execution frame.

---

## 14. What Plays the Role of "Inference"?

In standard LLMs, inference is sampling tokens one by one from a probability distribution: $w_t \sim P(w_t \mid w_{<t})$. This conflates understanding, planning, factual lookup, and syntax generation into a single stochastic step, inevitably producing hallucinations.

In Paartha, inference is **goal-directed, verified computational execution**:
$$\text{Ingress} \longrightarrow \text{Context Resolution} \longrightarrow \text{Capability / Search Dispatch} \longrightarrow \text{State Transition} \longrightarrow \text{Structural Verification} \longrightarrow \text{Surface Realization}$$

1. **Context Resolution**: The input utterance updates the `WorkingStateStore` slots.
2. **Dispatch / Search**:
   - For direct factual queries: Look up $\mathcal{E}_R$ or $S_{episodic}$; if missing, trigger clarification or declare "I do not know" (EXP-009, EXP-026).
   - For deductive queries: Apply invariant rules in $\mathcal{C}_I$ to derive a verified proof trace (KRS-001).
   - For multi-step or compositional goals: Execute SET-CR heuristic tree search over capability primitives in $\mathcal{L}$ with checkpoint rollback (GDR-003).
3. **Verification**: Validate candidate outputs against $S_{invariants}$ via `EVALUATE-STRUCTURAL`.
4. **Surface Realization**: Render the verified result or proof trace into natural language.

## 15. What Remains Unknown? (The Honest Open Questions)

Archaeology must be ruthlessly honest about what Paartha has NOT yet solved:

1. **The Natural Language Ingress & Grounding Gap**:
   - In `runtime/sip001/`, requests are structured JSON dictionaries (`{"kind": "teach_fact", "name": "Alice", "city": "Paris"}`).
   - In `runtime/aca0/`, lessons and queries are parsed via hardcoded string splitting (`"All mammals breathe air" -> cond="mammals", pred="breathe", target="air"`).
   - *Status*: **UNSOLVED**. Paartha has no verified, lightweight natural language parser that maps open-ended, ambiguous human text into working state slots or relational graph tuples without a large pretrained model.
2. **The Surface Realization / Fluent Generation Gap**:
   - In `runtime/aca0/`, explanations are generated via rigid string templates: `f"Because {subj}s are {cat}s, and all {cat}s {pred} {obj}."`
   - *Status*: **UNSOLVED**. Paartha does not yet possess a small, grounded linguistic decoder that can generate varied, natural, fluent English sentences from structured proof traces and working state without reverting to statistical hallucination.
3. **The Multi-Turn Natural Language Pragmatics Gap**:
   - Handling coreference ("Why did *they* do that?"), ellipsis ("What about dolphins?"), and shifting conversational focus across many turns in raw natural language has only been tested on synthetic slot-filling tasks (EXP-019), not real human dialogue.
4. **Continual Factual Retention at Scale**:
   - While EXP-022 solved single-exposure teaching for isolated facts via unconditional writes, EXP-031 demonstrated that under 1,000 sequential lessons, small memory buffers ($C=30$) collapse to $10.38\%$ historical recall. Memory consolidation into semantic parameters without forgetting remains fundamentally fragile (EXP-010, EXP-018).
