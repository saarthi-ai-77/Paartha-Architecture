## 1. Audit Objective

The objective of this audit is to determine whether `GDR-001` has discovered a **fundamental computational mechanism of goal-directed cognition**, or whether it has simply repeated a classic error in cognitive science: **converting an intuitive, descriptive decomposition of intelligent behavior into a rigid, premature architecture.**

The audit operates under strict methodological rules:
1. **Implementation Freeze:** PCE, the seven faculties as hard-coded modules, the Task AST, the Causal Repair Engine, and GDR-BENCH-0 are frozen. No runtime code will be written around these unvalidated constructs.
2. **Historical Continuity:** GDR-001 is preserved verbatim as an active research specification. This audit evaluates it from first principles, literature evidence, and computational bounds.
3. **Traceable Arbitration:** Every claim extracted from GDR-001 will receive an explicit epistemic classification and an evidentiary verdict tracing:
   $$\text{GDR-001 Claim} \longrightarrow \text{Audit Finding} \longrightarrow \text{Revised Status} \longrightarrow \text{Architectural Consequence}$$

## 2. Extraction of Core Claims from GDR-001

Twelve major claims form the structural backbone of GDR-001:

1. **Claim 1 (The Competence-Orchestration Gap):** A multi-substrate memory ($S_{episodic}, S_{semantic}, S_{invariants}$) and an isolated capability library ($\mathcal{L}$) provide *competence*, but are inert without an explicit goal-directed orchestration mechanism.
2. **Claim 2 (The Seven-Faculty Decomposition):** Goal-directed problem solving decomposes into seven functionally distinct, modular faculties: *Knowing, Computing, Selecting, Executing, Verifying, Recovering, and Communicating*.
3. **Claim 3 (Formal Task Formulation):** General problem solving can be uniformly formulated as a grounded task tuple $T = (G, s_0, \mathcal{C}, \mathcal{B})$ with explicit goal predicate $\Phi(s)$ and hard constraints $\mathcal{C}$.
4. **Claim 4 (Computational DAG as Planning Target):** The universal intermediate output of planning is a directed acyclic graph (DAG) of discrete computational primitives.
5. **Claim 5 (Task AST as Ingestion Interface):** Parsing natural language into a typed, structured Task AST is necessary to bridge human intent to formal computation without foundation LLM hallucinations.
6. **Claim 6 (Meta-Cognitive Strategy Selection Space):** The strategy selector operates over an explicit discrete space: Direct Lookup ($O(1)$), HTN Decomposition ($O(b \cdot d)$), Heuristic Search, and User Clarification.
7. **Claim 7 (Universal Invariant Verification):** Invariant verification via independent, non-generative contract evaluation $\text{Post}(P)$ is a universal requirement for robust reasoning.
8. **Claim 8 (Causal Fault Diagnosis & Local DAG Repair):** When execution fails, the system must localize causal credit to a specific DAG node/binding and perform targeted sub-DAG repair rather than trajectory resampling.
9. **Claim 9 (Dual-Loop Cognitive Engine - PCE):** General intelligence requires a bi-level architecture: an outer meta-cognitive strategy/goal-reduction loop decoupled from an inner bounded execution & contract-verification loop.
10. **Claim 10 (Decoupled Surface Realization & Hallucination Elimination):** Decoupling internal structured state from a constrained surface language generator makes factual hallucinations structurally impossible.
11. **Claim 11 (Reasoning Architecture Replaces Massive Pretraining):** Explicit goal-directed search and modular capability accumulation can replace foundation-scale pretraining for general reasoning tasks.
12. **Claim 12 (Universal Domain Sufficiency):** The proposed PCE mechanisms are sufficient to handle arbitrary user tasks ranging from code synthesis and distributed debugging to pragmatic email drafting and scientific synthesis.

## 5. Detailed Attack on the Seven-Faculty Decomposition

GDR-001 proposed:
$$\text{Knowing} \to \text{Computing} \to \text{Selecting} \to \text{Executing} \to \text{Verifying} \to \text{Recovering} \to \text{Communicating}$$

### 5.1 Reducibility and Conceptual Overlap
Does this reflect seven irreducible computational mechanisms, or is it an ad-hoc descriptive taxonomy?

1. **Selecting vs. Recovering:**
   * In GDR-001, "Selecting" takes state $s_0$ and goal $G$ and finds a plan $\pi$.
   * "Recovering" takes failed state $s_{fail}$ and goal $G$ and finds a repaired plan $\pi'$.
   * **Computational Reality:** *Recovering is simply selecting an action or trajectory conditioned on an unexpected state.* Treating "Recovery" as a separate faculty is equivalent to claiming that a chess engine has one faculty for moving from the opening and a completely separate faculty for moving after an opponent's surprise move. They are mathematically identical: search/policy evaluation over state space.
2. **Executing vs. Verifying:**
   * In any computational runtime, executing an operator $P(s)$ changes state to $s'$.
   * "Verifying" consists of executing an assertion function $A(s') \to \{0, 1\}$.
   * **Computational Reality:** Assertion functions are themselves operators in $\mathcal{L}$. An invariant checker is not a distinct faculty; it is an operator whose execution returns a boolean predicate. Separating "Verification" into a primary cognitive faculty confuses the *semantic purpose* of an operation with its *computational mechanism*.
3. **Knowing vs. Being Able to Compute:**
   * Under the Curry-Howard correspondence and modern computational models, declarative data and executable code are duals. Stored weights in a neural network represent both facts (memory) and computational transformations (functions).
   * While ACA v1.0 maintains an engineering separation between $S_{episodic}$ and $\mathcal{L}$, elevating this to a fundamental cognitive law creates false boundaries.
4. **Communication:**
   * Communication is an action executed in an environment containing other agents. Emitting text to a human is structurally identical to emitting SQL to a database or G-code to a machine tool: it is an action $a_t \in \mathcal{A}$ designed to alter external state.

### 5.2 The Underlying Fundamental Reduction
The seven faculties collapse without loss of generality into the classic **Cybernetic Control / POMDP Abstraction**:
1. **Internal State & Memory ($s \in \mathcal{S}$):** The accumulated representation of world, self, and task.
2. **Action / Operator Space ($\mathcal{A}$ or $\mathcal{L}$):** The repertoire of transitions available to the system.
3. **Objective / Value Function ($J(s, G)$):** The evaluation metric defining goal satisfaction and constraint costs.
4. **Policy / Search Optimization ($\pi: \mathcal{S} \times \mathcal{G} \to \mathcal{A}$):** The computational engine that selects transitions to minimize expected objective discrepancy.
5. **Observation / State Update ($\tau: \mathcal{S} \times \mathcal{O} \to \mathcal{S}'$):** Integrating feedback from execution, environment, or assertions into state.

```
       GDR-001 7-FACULTY TAXONOMY                    CYBERNETIC / POMDP REDUCTION
┌──────────────────────────────────────┐        ┌────────────────────────────────────┐
│ 1. Knowing (S_episodic)              │ ────>  │ Internal State & Memory (s in S)   │
│ 2. Computing (Library L)             │ ────>  │ Action / Operator Space (A or L)   │
│ 3. Selecting (Orchestrator)          │ ─┐     │                                    │
│ 6. Recovering (Repair Engine)        │ ─┴──>  │ Policy / Search Engine (pi: S -> A)│
│ 4. Executing (Runtime)               │ ─┐     │                                    │
│ 7. Communicating (Surface Realizer)  │ ─┴──>  │ Action Execution in Environment    │
│ 5. Verifying (Invariant Auditor)     │ ────>  │ Objective & Observation Update     │
└──────────────────────────────────────┘        └────────────────────────────────────┘
```

**Verdict on Section 5:** The Seven-Faculty Decomposition is an **intuitive descriptive convenience**, not an irreducible cognitive law. Treating it as a set of separate modules will create unnecessary architectural overhead and rigid boundaries.

## 6. Analysis of PCE (Paartha Cognitive Engine)

GDR-001 proposed the **Dual-Loop Cognitive Architecture (PCE)**: an outer meta-cognitive goal-reduction loop and an inner bounded execution & contract-verification loop.

### 6.1 Critique of the Dual-Loop Assumption
* **The Descriptive Fallacy:** PCE models human psychology (Kahneman's System 1 and System 2; Baddeley's Central Executive). However, psychological descriptions of human behavior do not automatically translate into optimal computational architectures.
* **The Synchronization Bottleneck:** In hierarchical control systems (Albus, 1991), rigid multi-loop hierarchies create severe coordination bottlenecks. When the inner loop encounters an impasse, how much context must be escalated to the outer loop? If full context is escalated, the outer loop becomes saturated; if minimal context is escalated, the outer loop plans blind.
* **The Missing Metric:** GDR-001 provides no mathematical criterion for when a problem should be handled by the outer loop vs. the inner loop, relying on qualitative descriptors ("slow, deliberate" vs. "fast, operational").

**Verdict on Section 6:** PCE is an **architectural design proposal (Standard D)**. It is a plausible engineering pattern for combining planning with execution (analogous to Model Predictive Control or Hierarchical Reinforcement Learning), but must NOT be treated as established theory.

## 7. Analysis of the Task AST and Semantic Ingestion

GDR-001 argued that natural language requests should be compiled into an explicit **Task AST** containing:
`{ intent, target_predicate, inputs, invariants }`

### 7.1 The Semantic Parsing Bottleneck
From 1995 to 2018, symbolic AI attempted to map natural language to formal logical forms (Zettlemoyer & Collins, 2005; Liang, 2016). Every such system suffered from catastrophic fragility:
1. **Expressive Underspecification:** Human language relies on pragmatics, shared context, and implicit defaults (Grice, 1975). Forcing human intent into a rigid JSON schema forces the parser to either invent parameters (hallucinating constraints) or drop vital nuances.
2. **Compounding Parser Failure:** In a pipeline of `Language -> Task AST -> Solver`, any error in the AST halts the solver. End-to-end models and latent-plan representations succeeded precisely because they avoid this hard syntactic cliff.
3. **Domain Narrowness:** An AST schema that works for graph algorithms (`FIND_MINIMAL_PATH`) is useless for interpersonal negotiation, debugging messy log files, or exploratory research.

**Verdict on Section 7:** The universal Task AST is **unsupported and fragile (Standard D/E)**. Structured intermediate representations should only be used as transient tool interfaces (e.g., generating a Python script or an SQL query), NOT as the universal substrate for internal thought.

## 8. Analysis of the Planning / DAG Assumption

GDR-001 assumed that planning produces a **Computational DAG** before execution begins.

### 8.1 Why Static DAGs Fail in Real-World Problem Solving
A directed acyclic graph represents static, feedforward dataflow. It assumes:
* All dependencies are known upfront.
* The environment does not change during execution.
* Control flow has no loops, breaks, or dynamic conditions.

However, consider the four motivating archetypes from GDR-001:
* **Debugging a Deadlock:** You cannot generate an upfront DAG of the solution because step 2 depends entirely on what thread dumps reveal at step 1. This requires **interactive, hypothesis-driven experimentation**, not static DAG execution.
* **Writing an Email:** The generation of paragraph 2 dynamically influences the stylistic balance of paragraph 3. Imposing a DAG over language tokens is an artificial constraint.

### 8.2 The Stronger Alternative: Reactive Search with Receding Horizon
Rather than generating an upfront static DAG, robust autonomous systems utilize **Receding Horizon Planning / Model Predictive Control (MPC)** or **Monte Carlo Tree Search (MCTS)**:
1. Conduct local lookahead search from current state $s_t$.
2. Select the most promising immediate action $a_t$.
3. Execute $a_t$, observe true environment feedback $o_{t+1}$, and update internal state to $s_{t+1}$.
4. Re-plan from $s_{t+1}$.

**Verdict on Section 8:** The static Computational DAG is an **overly rigid design choice (Standard D)**. It is suitable only for deterministic, closed-world subroutines. General problem solving requires **closed-loop reactive execution with lookahead**.

## 9. Analysis of the Verification Thesis

GDR-001 elevated independent invariant verification to a mandatory cornerstone of reasoning.

### 9.1 The Tripartite Reality of Ground Truth
Verification is only well-defined when an objective decision procedure exists. In reality, problem domains fall into three fundamentally distinct classes:

```
+----------------------------------------------------------------------------------------------------+
|                               THE TRIPARTITE GROUND TRUTH SPECTRUM                                 |
+----------------------------------------------------------------------------------------------------+
|                                                                                                    |
|  CLASS 1: CLOSED FORMAL DOMAINS (Objective, Decidable Ground Truth)                                |
|  * Domains: Compilers, unit tests, formal math, SAT/SMT solvers, closed-loop games.                |
|  * Verification Mechanism: Deterministic contract check Post(P) == True.                           |
|  * GDR-001 Status: FULLY VALIDATED. Independent verification dramatically outperforms verbal CoT.  |
|                                                                                                    |
|  CLASS 2: OPEN EMPIRICAL DOMAINS (Partial, Stochastic Ground Truth)                                |
|  * Domains: Code debugging, scientific research, data extraction, web search.                      |
|  * Verification Mechanism: Incomplete tests, heuristic invariants, statistical confidence intervals. |
|  * GDR-001 Status: PARTIALLY APPLICABLE. Requires probabilistic hypothesis testing, not binary post.|
|                                                                                                    |
|  CLASS 3: SUBJECTIVE & PRAGMATIC DOMAINS (No Objective Ground Truth)                              |
|  * Domains: Writing persuasive emails, strategic design, creative synthesis, ethical trade-offs.   |
|  * Verification Mechanism: Multi-objective constraint satisficing, preference modeling, user critique.|
|  * GDR-001 Status: UNSUPPORTED. Formal contract checking is impossible; requires interactive alignment.|
|                                                                                                    |
+----------------------------------------------------------------------------------------------------+
```

**Verdict on Section 9:** Invariant verification is **not universal (Standard B for Class 1, Standard E for Class 3)**. An architecture that requires deterministic postcondition checking will either reject valid solutions in subjective domains or invent arbitrary pseudochecks.

## 10. Analysis of the Failure-Recovery Model

GDR-001 proposed:
$$\text{Failed Node} \longrightarrow \text{Diagnose Root Cause} \longrightarrow \text{Targeted Local DAG Repair}$$

### 10.1 The Intractability of Causal Diagnosis
1. **The Credit Assignment Problem:** When a multi-stage process fails, localizing fault to a single operator is often mathematically impossible without exhaustive counterfactual rollouts (Pearl, 2000). A failure at step 6 is frequently caused by a subtle, non-violating inaccuracy introduced at step 2.
2. **Coupled State Side-Effects:** If primitives mutate external state (files written, network requests sent, memory allocated), simply "replacing node 4" leaves the environment corrupted.
3. **Empirical Results from Automated Program Repair (APR):** In software engineering, systems that attempt deep causal root-cause diagnosis (e.g., semantic fault localization) are routinely outperformed by stochastic search and template-based test-suite sampling (Goues et al., 2012; Le Goues et al., 2019).

### 10.2 The Robust Alternative: Checkpoint State Rollback
Instead of complex causal attribution, the standard, reliable mechanism in computing is:
$$\text{Snapshot Checkpoint State } s_{chk} \longrightarrow \text{Execute with Timeout/Assertion} \longrightarrow \text{On Failure: Rollback to } s_{chk} \text{ and Branch}$$
This requires zero causal attribution machinery: it relies entirely on state checkpointing and alternative action selection.

**Verdict on Section 10:** The Causal Repair Engine is an **unsupported complexity trap (Standard D/E)**. State checkpointing, rollback, and branching search provide superior reliability with dramatically simpler mechanics.

## 11. Analysis of Decoupled Communication & Hallucination Elimination

GDR-001 made the following assertion:
> *"Translating a verified symbolic computational result into natural language via a separate surface generator maintains 100% factual fidelity... Hallucinations are structurally impossible."*

### 11.1 Empirical Refutation from Natural Language Generation (NLG)
This assertion is **scientifically false**. In data-to-text generation, neural surface realizers conditioned on verified database tables, execution graphs, or Knowledge Graph triples routinely produce:
* **Extrapolation Hallucination:** Inventing plausible narrative links not supported by the underlying data (Wiseman et al., 2017; Dusek et al., 2020).
* **Binding Inversion:** Swapping subjects and objects while generating passive voice constructions.
* **Omission of Modifiers:** Dropping conditional qualifiers (e.g., turning *"algorithm terminates in O(V) if graph is acyclic"* into *"algorithm terminates in O(V)"*).

Unless the surface realizer is a **deterministic, non-neural string template** (which completely destroys communicative flexibility and fails on open-ended requests), a neural generator **can and will hallucinate**.

**Verdict on Section 11:** The claim that hallucinations are "structurally impossible" is **OVERCLAIMED AND FALSIFIED (Standard E)**. Decoupling internal state from communication reduces factual errors by grounding generation, but cannot eliminate linguistic hallucination without deterministic templates.

## 12. Analysis of the Minimal-Pretraining Claim

GDR-001 posited that explicit reasoning architectures can largely eliminate the need for massive pretraining.

### 12.1 What Search Can and Cannot Replace
Rich Sutton's *The Bitter Lesson* (2019) establishes that general methods leveraging search and learning scale with compute, while hand-coded modular structures do not. 

More specifically, we must delineate what test-time search can replace versus what requires massive data:
* **What Search CAN Replace:** Combinatorial trajectory exploration, formal algorithmic synthesis, and logical constraint verification (AlphaZero, o1, FlashFill).
* **What Search CANNOT Replace:** 
  * World knowledge (e.g., knowing that a professor typically expects formal salutations, or that distributed deadlock often involves network partitions).
  * Commonsense semantics (grounding words to physical and social realities).
  * Heuristic prior evaluation (an unguided search tree over infinite actions has branching factor $b = \infty$ and depth $d = \infty$; without strong learned priors, search is blind).

### 12.2 Taxonomic Clarification of Learning Regimes
Paartha must strictly distinguish five distinct operational regimes:

```
+----------------------------------------------------------------------------------------+
|                               FIVE LEARNING REGIMES                                    |
+----------------------------------------------------------------------------------------+
|  1. Tabula Rasa (Zero Pretraining)                                                     |
|     * Works for: Chess, Go, closed synthetic gridworlds.                               |
|     * Fails for: Natural language, real-world tasks, open-ended problem solving.       |
|                                                                                        |
|  2. Compact Base SLM (10M - 500M parameters)                                           |
|     * Embeds: Basic syntax, lexical associations, grammatical structure.               |
|     * Lacks: Deep commonsense reasoning and encyclopedic knowledge.                    |
|                                                                                        |
|  3. Task-Specific Bootstrapping (DreamCoder)                                           |
|     * Compresses domain DSLs via wake-sleep program synthesis.                         |
|     * Fails: Beyond closed symbolic micro-worlds.                                      |
|                                                                                        |
|  4. Continual Mentor-Guided Capability Distillation (The Paartha Target)               |
|     * Base: Compact pretrained or seeded model.                                        |
|     * Learning: Incremental acquisition of verified primitives into library L.         |
|     * Problem Solving: Inference-time search over L with state checkpointing.           |
|                                                                                        |
|  5. Massive Foundation Pretraining (100B+ parameters)                                  |
|     * Brute-force entrainment of knowledge, grammar, and reasoning in one parameter set.|
+----------------------------------------------------------------------------------------+
```

**Verdict on Section 12:** Claiming Paartha solves general problems "without massive pretraining" without specifying the alternative knowledge source is an **overclaim (Standard E)**. Paartha's true scientific proposition is **Regime 4: A compact model augmented with continual mentor-guided capability acquisition and inference-time search**, NOT magic tabula rasa reasoning.

## 13. Search for Deeper Common Abstractions

We reject the 7-faculty taxonomy and the static PCE dual loop as premature architectures. What is the **minimal computational process** that transforms an arbitrary goal into successful computation?

### 13.1 Survey of Unified Abstractions
1. **The TOTE Unit (Miller, Galanter, Pribram, 1960):**
   $$\text{Test (Discrepancy Check)} \longrightarrow \text{Operate} \longrightarrow \text{Test} \longrightarrow \text{Exit}$$
2. **Active Inference / Free Energy Minimization (Friston, 2010):**
   Agents maintain internal generative models and act to minimize the divergence (free energy) between preferred observations (goals) and actual sensory observations.
3. **Closed-Loop Feedback Control (Wiener, 1948):**
   $$\text{Error } e(t) = G - y(t) \longrightarrow \text{Controller } u(t) = K(e) \longrightarrow \text{Plant } \dot{x} = f(x, u) \longrightarrow \text{Measurement } y(t)$$
4. **Iterative Program Refinement (Inductive Synthesis):**
   $$\text{Specification} \longrightarrow \text{Sample Candidate Program } P \longrightarrow \text{Execute } P \longrightarrow \text{Observe Delta} \longrightarrow \text{Refine } P$$

### 13.2 The Minimal Unified Abstraction: Closed-Loop Discrepancy Reduction (CDR)
Underneath planning, synthesis, debugging, and execution lies a single universal computational loop:

```
                             GOAL SPECIFICATION G
                                      │
                                      ▼
                        ┌───────────────────────────┐
                        │   Discrepancy Evaluator   │ <──────────────────────┐
                        │    Delta = D(s_t, G)      │                        │
                        └───────────────────────────┘                        │
                                      │                                      │
                         Delta <= epsilon or Budget = 0                      │
                               ┌──────┴──────┐                               │
                             YES             NO                              │
                              │              │                               │
                              ▼              ▼                               │
                            HALT     ┌───────────────────────┐               │
                                     │ Policy / Action Search│               │
                                     │    a_t ~ pi(s_t, G)   │               │
                                     └───────────────────────┘               │
                                             │                               │
                                             ▼                               │
                                     ┌───────────────────────┐               │
                                     │  Execute Operator P   │               │
                                     │   on State Snapshot   │               │
                                     └───────────────────────┘               │
                                             │                               │
                                             ▼                               │
                                     ┌───────────────────────┐               │
                                     │ State Transition &    │ ──────────────┘
                                     │ Observation Update    │
                                     │ s_{t+1} = tau(s_t, P) │
                                     └───────────────────────┘
```

**Why this abstraction is superior:**
* It does not mandate an upfront planner: if a direct primitive exists, $\pi$ fires it immediately ($O(1)$).
* It does not mandate an upfront DAG: complex, interactive problems unfold step-by-step through execution feedback.
* It does not mandate a separate "Recovery" engine: failure simply changes state $s_t$ such that $\Delta(s_t, G)$ remains large, causing the search policy to select an alternative action from the current or rolled-back state.
* It natively unifies code execution, search, active inquiry, and conversation into a single mathematical loop.

## 15. What Survives the Audit

The following core findings and principles survive adversarial critique:

1. **The Competence-Orchestration Gap (Established):** Storing primitives in $\mathcal{L}$ and facts in memory is inert without an autonomous, goal-directed driver.
2. **Inference-Time Search Replaces Parameter Scaling in Formal Domains (Established):** In closed, verifiable domains, test-time compute search over modular operators outperforms large models evaluated greedily.
3. **Decoupled Working Memory Is Mandatory (Established):** Working state must reside in a dedicated, reserved partition ($S_{working}$) with unconditional write semantics to prevent write starvation during multi-step reasoning (EXP-019).
4. **Invariant Auditing Beats Verbal Self-Reflection (Supported):** Deterministic contract verification is demonstrably superior to autoregressive verbal critique ("Reflexion") in domains where formal ground truth exists.
5. **Closed-Loop Discrepancy Reduction (CDR) as the Core Loop (Plausible):** All goal-directed reasoning fundamentally reduces to iterative state-action discrepancy reduction with state checkpointing and rollback.

## 18. Revised Minimal Scientific Research Question

Stripping away premature modular architecture and taxonomic labels yields the true, minimal, falsifiable research question for this phase:

> **Can a compact AI system, equipped with a library of isolated computational primitives and a reserved working state, use inference-time search over state-action transitions to solve previously unseen multi-step tasks and recover from intermediate execution faults without retraining its base parameters?**

This question is:
* **Architecture-independent:** Does not depend on 7 faculties, 2 loops, or custom ASTs.
* **Falsifiable:** Can be directly measured by task completion and recovery rates under fault injection.
* **Tractable:** Can be evaluated on minimal compute without foundation-scale clusters.
* **Core to Paartha:** Directly bridges the gap between EXP-033 (capability acquisition) and autonomous problem solving.

## 19. Revised Experimental Direction

### 19.1 Arbitration on GDR-BENCH-0
* **Original GDR-001 Proposal:** Build `GDR-BENCH-0` to implement the full 7-faculty PCE architecture, Task AST parser, and Causal Repair Engine.
* **Audit Verdict:** **REJECTED AS PREMATURE.** Implementing PCE now would be building a massive scaffold around an unverified taxonomy.
* **Revised Proposal:** Replace `GDR-BENCH-0` with **`EXP-CCS-0` (Capability Composition via Search - Benchmark 0)**.

### 19.2 Experimental Specification: EXP-CCS-0
* **Objective:** Test whether simple heuristic tree search (MCTS / receding-horizon search) over isolated computational primitives with state rollback solves multi-step composition and recovers from execution faults, without requiring an upfront DAG planner or causal repair engine.
* **Environment:** A deterministic state VM containing:
  * 5 verified primitives in $\mathcal{L}$: `Sort`, `Filter`, `Join`, `Project`, `Aggregate`.
  * Reserved working memory partition $S_{working}$.
  * Formal test assertions for terminal goal check $\Phi(s^*)$.
* **Experimental Arms:**
  * **Arm 1 (Upfront Static DAG Planning):** Synthesize entire plan upfront; execute sequentially; abort on fault.
  * **Arm 2 (GDR-001 Causal Repair):** Upfront plan with node-level causal diagnosis and local patch.
  * **Arm 3 (Closed-Loop Discrepancy Reduction - CDR with Rollback):** Step-by-step lookahead search with checkpointing. Upon assertion failure, rollback to parent checkpoint and branch on alternative operator.
  * **Baseline (Autoregressive Token Generation):** Small language model generating end-to-end code/plan greedily.
* **Independent Variables:**
  * Task dependency depth $d \in \{2, 4, 6, 8\}$.
  * Fault injection rate ($0\%$ vs. $30\%$ corrupted intermediate states).
* **Dependent Metrics:**
  * Task Success Rate ($TSR = \frac{\text{Solved Tasks}}{\text{Total Tasks}}$).
  * Compute Overhead (Total state transitions evaluated).
  * Recovery Success Rate ($RSR$ under injected faults).
* **Falsification Criteria for CDR:** If Arm 3 does not achieve $\ge 2\times$ higher recovery success than Arm 1 and match or exceed Arm 2's accuracy with $<50\%$ of the code complexity, the CDR abstraction is insufficient.
