# VP-001: Validation Program Specification

**Role note:** Produced under the Chief Systems Engineer role for **VP-001 ("Validation Program")**. Following ACA-0's 100% benchmark validation (`docs/17_knowledge/KRS-001.md`, EXP-026), the research program shifts from architectural expansion to rigorous adversarial validation.

**Adversarial Scientific Stance:** Assume ACA is incorrect until evidence demonstrates otherwise. Every experiment is designed to expose weaknesses, contradictions, hidden assumptions, scalability limits, or architectural failures.

---

## 1. The 10 Validation Domains

VP-001 establishes ten comprehensive validation test suites designed to stress ACA v1.0, ACA-0, CPA-001, LRS-001, KRS-001, and CUR-001:

```
+-------------------------------------------------------------------------------+
|                           THE 10 VALIDATION DOMAINS                           |
+-------------------------------------------------------------------------------+
| Domain 1: Contradictory Knowledge      | Mutually inconsistent lessons        |
| Domain 2: Knowledge Evolution         | Information correction & updates      |
| Domain 3: Confidence & Uncertainty    | Ambiguous & probabilistic lessons     |
| Domain 4: Source Reliability          | Trusted vs untrusted mentor sources   |
| Domain 5: Long-Term Continual Learning| 1,000+ sequential lessons & memory    |
| Domain 6: Multi-Domain Transfer       | Cross-domain structural abstraction   |
| Domain 7: Noisy Instruction           | Typos, broken syntax & ambiguous text |
| Domain 8: Adversarial Teaching        | Misleading & deceptive mentors        |
| Domain 9: Curriculum Robustness       | Out-of-order & un-grounded lessons    |
| Domain 10: Emergent Failure Modes     | Unpredicted systemic breakdowns       |
+-------------------------------------------------------------------------------+
```

---

### 1.1 Domain 1 — Contradictory Knowledge
- **Test Protocol**: Teach lesson $A$ ("Whales are mammals"), then lesson $B$ ("Whales are fish").
- **Evaluated Target**: Does $S_{invariants}$ audit detect contradiction, assign `CLARIFICATION_REQUIRED`, and reject inconsistent updates without state corruption?
- **Primary Falsification ID**: `EXP-027` (Domain 1 Falsification Trial).
- **Epistemic Status**: **Reasoned Hypothesis** (Derived from CTX-001 audit requirements).

---

### 1.2 Domain 2 — Knowledge Evolution
- **Test Protocol**: Teach obsolete fact $K_{old}$ ("Pluto is a planet"), followed by correction $K_{new}$ ("Pluto is a dwarf planet").
- **Evaluated Target**: Does ACA execute clean belief revision in $S_{episodic}$ and $S_{semantic}$ without leaving residual contradictory facts?
- **Primary Falsification ID**: `EXP-028` (Domain 2 Belief Revision Trial).
- **Epistemic Status**: **Reasoned Hypothesis** (Derived from SOS-001 primary write rules).

---

### 1.3 Domain 3 — Confidence & Uncertainty
- **Test Protocol**: Issue probabilistic or under-specified lessons ("It usually rains in April").
- **Evaluated Target**: Does EVALUATE-LOCAL emit well-calibrated intermediate entropy ($0.5 \le H < 1.5$ nats) and assign `PARTIALLY_UNDERSTOOD` state?
- **Primary Falsification ID**: `EXP-029` (Domain 3 Uncertainty Calibration Trial).
- **Epistemic Status**: **Validated** (Entropy signals validated by EXP-009).

---

### 1.4 Domain 4 — Source Reliability
- **Test Protocol**: Introduce multiple mentors with varying reliability scores $R_{mentor} \in [0, 1]$.
- **Evaluated Target**: Does source trust weighting modulate $S_{episodic}$ write acceptance and $S_{semantic}$ promotion gates?
- **Primary Falsification ID**: `EXP-030` (Domain 4 Mentor Trust Trial).
- **Epistemic Status**: **Reasoned Hypothesis** (Extension of LRS-001 interaction protocols).

---

### 1.5 Domain 5 — Long-Term Continual Learning ($1,000+$ Lessons)
- **Test Protocol**: Stream 1,000 sequential lessons across 50 domains under capacity $C=30$.
- **Evaluated Target**: Does CPA-001 INV-1 pre-eviction promotion hold under long-term capacity pressure, or does catastrophic forgetting recur at scale?
- **Primary Falsification ID**: `EXP-031` (Domain 5 1k-Lesson Stability Trial).
- **Epistemic Status**: **Open Question** (Tracks HYP-008).

---

### 1.6 Domain 6 — Multi-Domain Transfer
- **Test Protocol**: Teach structural rules in Domain $A$ (e.g. arithmetic group symmetries).
- **Evaluated Target**: Does COMPOSE transfer abstract transform templates to unrelated Domain $B$ (e.g. spatial navigation)?
- **Primary Falsification ID**: `EXP-032` (Domain 6 Abstract Transfer Trial).
- **Epistemic Status**: **Validated** (Grounded in EXP-020 SCAN transfer).

---

### 1.7 Domain 7 — Noisy Instruction
- **Test Protocol**: Corrupt instructional text with typos, missing words, and inconsistent terminology ($p_{noise} \in [0.05, 0.30]$).
- **Evaluated Target**: Does COMPOSE parsing degrade gracefully, or emit `CLARIFICATION_REQUIRED` for broken syntax?
- **Primary Falsification ID**: `EXP-033` (Domain 7 Noise Robustness Trial).
- **Epistemic Status**: **Validated** (Noise curves validated by EXP-023).

---

### 1.8 Domain 8 — Adversarial Teaching
- **Test Protocol**: Deceptive mentor presents false premises ("All mammals live underwater") and malicious proofs.
- **Evaluated Target**: Does $S_{invariants}$ audit reject deceptive claims, or does ACA accept false beliefs?
- **Primary Falsification ID**: `EXP-034` (Domain 8 Deceptive Mentor Trial).
- **Epistemic Status**: **Reasoned Hypothesis** (Tracks HYP-007).

---

### 1.9 Domain 9 — Curriculum Robustness
- **Test Protocol**: Intentionally violate CUR-001 by presenting rules before entity category grounding or skipping prerequisites.
- **Evaluated Target**: Quantifies exact degradation curve and confirms whether curriculum ordering is a strict computational requirement (CUR-001 Theorem 1.1).
- **Primary Falsification ID**: `EXP-035` (Domain 9 Out-of-Order Lesson Trial).
- **Epistemic Status**: **Reasoned Hypothesis** (Tracks HYP-006).

---

### 1.10 Domain 10 — Emergent Unpredicted Failure Modes
- **Test Protocol**: Unconstrained stress testing across multi-mentor, multi-session, multi-task workloads.
- **Evaluated Target**: Uncovers unpredicted, emergent failure modes and classifies them across the 8 standard failure categories.
- **Primary Falsification ID**: `EXP-036` (Domain 10 Emergent Failure Trial).
- **Epistemic Status**: **Open Question**.

## 2. The 8-Category Failure Classification Framework

Every observed experimental failure MUST be classified into exactly one of eight canonical failure categories:

| Category ID | Name | Description / Root Cause | Action Discipline |
|---|---|---|---|
| **Cat 1** | Implementation Bug | Software bug, syntax error, or pipeline coding defect | Fix code without changing architecture |
| **Cat 2** | Representation Limitation | KRS-001 knowledge graph unable to represent complex relation | Refine KRS-001 primitives |
| **Cat 3** | Learning Limitation | LRS-001 learning protocol insufficient for complex task | Refine LRS-001 verification protocol |
| **Cat 4** | Memory Limitation | $S_{episodic}$ capacity $C$ exceeded before promotion | Enforce CPA-001 INV-1 staging hooks |
| **Cat 5** | Reasoning Limitation | Deductive engine unable to unroll multi-hop proof | Expand KRS-001 reasoning engine |
| **Cat 6** | Curriculum Limitation | Lesson sequence violated prerequisite DAG ($\mathcal{G}_{curriculum}$) | Re-order lessons per CUR-001 topological sort |
| **Cat 7** | Architectural Limitation | Core ACA v1.0 function or substrate insufficient | Escalate to DEC-006 4-step gate |
| **Cat 8** | Theoretical Contradiction | Empirical observation contradicts foundational theory | Preserved and escalated to CTO |

- **Epistemic Status**: **Validated** (Framework adopted from DEC-006 & EXP-022/024/025).
